# Data Quality Traps — 数据质量陷阱识别

## R — 原文 (Reading)

> "由于金融时间序列是非平稳的，数据越多并不意味着回测在统计上越可靠。在判断一项策略的适用性时，要重点关注其近几年的业绩，而不要被包括早年光鲜数字的总体业绩欺骗。"
>
> — Ernest P. Chan, 第2章 2.2.5

## I — 方法论骨架 (Interpretation)

金融数据与物理/生物数据根本不同：**数据生成过程本身在变**。因此"大样本更可靠"的统计学直觉在这里 **反向成立**。五大陷阱：

1. **存活偏差（Survivorship Bias）**：数据库只含当前存续的证券，退市/破产股被删除。对"便宜买进"策略影响最严重——那些便宜股之所以便宜，可能正是因为即将破产。
2. **前视偏差（Look-ahead Bias）**：使用了交易完成后才知道的信息。例如"在日最低价 1% 内买入"——当日收盘前不可能知道日最低价。
3. **数据迁就偏差（Data-snooping Bias）**：过度调参以拟合历史噪声，参数越多越严重。
4. **未调整的价格数据**：未做分拆和股息调整的价格会产生虚假交易信号（除息日"暴跌"被当成真跌）。调整方法必须"乘因子"而非"减金额"以保持日收益率不变。
5. **非平稳性 / 状态转换**：市场结构、监管、竞争在变，10 年前的数据已不代表今天。

操作法则：
- 重点看 **近 3-5 年** 业绩，不要被总体长期业绩数字欺骗。
- 购买"无存活偏差"的数据集，或明确认识偏差影响（如 ca011 作者用 HQuotes 两年仍盈利，因为日内策略受影响小）。
- 价格数据必须"乘因子"调整；自己调整易错，建议购买已调整数据。
- 用前视偏差检测程序：移除最近 N 天数据，比较推荐头寸是否一致。

## A1 — 书中的应用 (Past Application)

### 案例 1: 使用有存活偏差的 HQuotes 数据仍盈利两年（ca011）
- **问题**: Chan 早期独立交易时使用雅虎财经的 HQuotes 数据，事后发现该数据**有存活偏差**。
- **方法论的使用**: Chan 认识到数据局限，但选择做日内交易策略——这类策略受存活偏差影响较小（持仓期短，退市风险低）。
- **结论**: "只要能够认识到工具和数据的局限性，你还是可以通过各种办法取得成功的。"
- **结果**: 两年多持续盈利，甚至他认识的一名 10 倍交易量的交易员也用同样数据且盈利。

### 案例 2: 博客读者否定季节性策略（ca007）
- **问题**: 金融学教授提出的季节性股票策略，早年回测优异。
- **方法论的使用**: 读者用近年数据快速检验，发现已失效（非平稳性 + 竞争）。
- **结论**: 10 年前的光鲜数据 ≠ 今天可用；状态转换和竞争会让策略失效。
- **结果**: Chan 自己的回测证实读者正确，避免了实盘损失。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 拿到一份历史数据集（免费或付费），想知道能否直接用于回测。
2. 回测结果"好得不真实"（S > 5，10 年稳定盈利），怀疑有偏差。
3. 复现 10+ 年前论文的策略，发现近年完全失效。

### 语言信号

- "数据有存活偏差吗 / is the data survivorship-bias free"
- "回测好得不真实 / backtest looks too good"
- "为什么 10 年前的策略现在不灵 / why old strategies fail"
- "数据要不要调整 / do I need adjusted prices"
- "前视偏差怎么查 / how to check look-ahead bias"

### 与相邻 skill 的区分

- 与 `strategy-screening-six-questions` 的区别：六问中问题 4/5 是数据陷阱的 **快速筛查**；本 skill 提供 **深度排查** 方法和检测程序。
- 与 `parameter-complexity-overfitting` 的区别：本 skill 管"数据本身"，后者管"模型怎么被数据骗"。
- 与 `transaction-cost-impact` 的区别：本 skill 管"数据质量"，后者管"执行成本"——两者独立且都要验证。

## E — 可执行步骤 (Execution)

1. **数据源盘点**：列出数据来源、时间跨度、是否含退市股、是否已调整分拆/股息。
   - 完成标准：输出数据清单 + 每项"存活偏差状态"和"调整状态"。

2. **五项偏差逐一检查**：
   - 存活偏差：数据是否含当前已退市证券？
   - 前视偏差：策略信号是否只使用滞后数据（上一交易日数据）？
   - 数据迁就偏差：参数数量 × 252 ≤ 数据点数？
   - 价格调整：是否用"乘因子"而非"减金额"？
   - 非平稳性：近 3-5 年子样本是否仍成立？
   - 完成标准：每项输出 Pass/Fail/Warning。

3. **前视偏差检测程序**（若前视偏差存疑）：
   - 移除最近 N 天（如 30 天）数据，重跑策略，比较推荐头寸与原始一致。
   - 完成标准：一致 → Pass；不一致 → 定位具体使用未来信息的代码行。

4. **综合判定**：
   - 全部 Pass → 进入 `transaction-cost-impact` 核算成本。
   - 任一 Fail → 数据不可用，必须更换数据源或重构信号。
   - Warning → 标注风险，进入策略分析时附加"近年业绩权重更高"的约束。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 交易的是 ETF/期货（无存活偏差困扰）——但仍需检查价格调整和前视偏差。
- 用户做纯基本面研究、不涉及时间序列回测——本 skill 不适用。
- 数据已经通过权威供应商（如 CRSP、Compustat）验证——不必重复检查。

### 作者在书中警告的失败模式

- **ce04**: 存活偏差——破产/收购的股票从数据库消失，人为抬高均值回归策略业绩。
- **ce05**: 前视偏差——"在日最低价 1% 内买入"这种规则隐含使用未来信息。
- **ce06**: 数据窥探偏差——100 个参数可以完美拟合历史，但未来业绩截然不同。

### 作者的盲点 / 时代局限

- 书中以 2009 年美股为默认场景；2026 年加密市场、期权市场、跨境套利场景下数据陷阱形态不同（如链上数据存在"重组织"问题，类似存活偏差）。
- 作者建议"直接购买已调整数据"——但 2026 年很多免费数据源（Yahoo、Alpha Vantage）调整算法不透明，需用户自查。
- 非平稳性的"近年业绩优先"原则，未给出精确定义（几年算"近年"？）；2026 年实践建议至少覆盖一个完整市场周期。

### 容易混淆的邻近方法论

- "数据越多越好" 在金融中是 **反向陷阱**，违反直觉。
- "调整过" ≠ "正确调整" —— 必须确认是"乘因子"而非"减金额"。
