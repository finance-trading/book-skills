# Strategy Selection Four Constraints — 策略选择四要素约束框架

## R — 原文 (Reading)

> "一项策略可行与否通常并不取决于策略本身，而取决于使用策略的人。你有 多少时间可以用来完善你的交易程序？你的编程能力如何？你的资本规模有多大？你的目标是稳定的月度收入还是追求大额的长期资本收益？"
>
> — Ernest Chan, 第2章 2.1节 line 761-764, 1262-1274

---

## I — 方法论骨架 (Interpretation)

这个框架的核心是：**策略选择不是"哪个最好"，而是"哪个我能做"**。

方法论骨架：
1. **逆向思维**：不是先找到"好策略"再看自己能不能做，而是先评估自己的约束条件，再看哪些策略在约束内。
2. **四大约束维度**：
   - **工作时间**：全职可做日内均值回归（需盯盘），兼职只能做日频/周频动量策略。
   - **编程水平**：初级只能做Excel可实现的简单策略，高级可做MATLAB/Python复杂系统。
   - **交易资本**：资本规模决定能做哪些策略（详见capital-scale-determines-strategy）。
   - **目标**：稳定收入vs资本增长vs学习经验，不同目标对应不同策略类型。
3. **约束的硬软之分**：
   - 硬约束：资本规模、编程水平（短期难改变）
   - 软约束：工作时间、目标（可调整）
4. **筛选流程**：
   - 第一步：列出四个约束的具体值
   - 第二步：排除违反硬约束的策略
   - 第三步：在剩余策略中按夏普比率排序
   - 第四步：选择夏普比率最高且符合目标的策略

关键洞察：**约束不是限制，而是筛选器**。它帮你快速淘汰80%不适合的策略，聚焦在20%真正可行的策略上。

## A1 — 书中的应用 (Past Application)

### 案例 1: 全职vs兼职交易者的策略选择
- **问题**: 用户问"我应该做日内交易还是日线交易？"
- **方法论的使用**: 先评估工作时间约束。如果能全职盯盘（每天6小时+），可以做日内均值回归策略；如果只能兼职（每天1-2小时），只能做日频/周频策略。
- **结论**: 工作时间是硬约束，决定了策略的持有期频率。
- **结果**: 避免了"想做日内但没时间盯盘"的常见错误。

### 案例 2: 资本规模决定策略类型
- **问题**: 用户问"我只有5万美元，能做什么策略？"
- **方法论的使用**: 资本规模是硬约束。5万美元账户不能做高频交易（需要大容量），不能做大盘股配对交易（需要高杠杆），只能做小容量策略（交易频繁、持仓少、标的少）。
- **结论**: 资本规模决定了策略的容量类型（详见capital-scale-determines-strategy）。
- **结果**: 避免了"小资本做大策略"的不匹配错误。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **策略选择困难**：用户列举了很多策略，不知道哪个适合自己。
2. **约束条件不清**：用户没有明确自己的工作约束（时间、资本、技能），直接问"哪个策略最好"。
3. **策略不匹配**：用户选择了与自己约束不匹配的策略（如兼职做日内）。
4. **目标模糊**：用户说不清自己的目标是稳定收入还是资本增长。

### 语言信号 (用户的话里出现这些就应激活)

- "我应该选什么策略？"
- "哪个策略最好？"
- "这个策略适合我吗？"
- "我只有X万资本，能做什么？"
- "What strategy should I pick?"
- "How to choose a strategy?"
- "Is this strategy right for me?"

### 与相邻 skill 的区分

- **与 `simple-first-principle` 的区别**: 本skill关注"约束条件"（我能做什么），simple-first关注"质量标准"（好策略长什么样）。本skill是筛选器，simple-first是质量过滤器。
- **与 `capital-scale-determines-strategy` 的区别**: 本skill是四要素框架（时间、编程、资本、目标），capital-scale是其中"资本"要素的展开。本skill是总框架，capital-scale是子模块。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **列出四大约束的具体值**
   - 完成标准: 用户能明确回答：每天能花多少时间？编程水平如何（初级/中级/高级）？可用交易资本多少？目标是什么（稳定收入/资本增长/学习）？
   - 判停条件: 若用户无法回答任一问题，引导其思考后再继续。

2. **标记硬约束**
   - 完成标准: 用户能区分哪些是硬约束（短期难改变：资本、编程水平），哪些是软约束（可调整：时间、目标）。
   - 判停条件: 若硬约束过严（如资本<5万），警告量化交易可能不适合，建议先积累资本。

3. **排除违反硬约束的策略**
   - 完成标准: 用户能列出所有考虑的策略，并标记哪些违反硬约束（如兼职做日内、小资本做大容量）。
   - 判停条件: 若所有候选策略都违反硬约束，返回步骤1调整目标或约束。

4. **在剩余策略中按夏普比率排序**
   - 完成标准: 用户能列出剩余可行策略的夏普比率，并按从高到低排序。
   - 判停条件: 若无策略夏普比率>1，考虑策略开发而非选择现成策略。

5. **选择符合目标的策略**
   - 完成标准: 用户能从排序后的策略中选择最符合目标的一个（如稳定收入选夏普最高，资本增长选增长率最高）。
   - 判停条件: 完成。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **策略优化场景**：用户已经确定了策略，只是想知道如何优化参数。本skill只用于策略选择，不用于策略优化。
- **纯理论讨论**：用户在问"哪种策略类型理论上最好"，而不是"我应该用哪种策略"。本skill是实操框架，不是理论框架。
- **学术研究**：用户在写论文，需要比较不同策略的学术价值。本skill是个人决策框架，不是学术评价框架。

### 作者在书中警告的失败模式

- **ce26 - 没有足够的存款撑过收入空窗期**: 资本约束不仅是"能做多少"，还是"能撑多久"。没有足够存款会导致财务压力，进而导致情绪化决策。
- **ce25 - 快速致富的心态**: 目标约束不仅是"想要多少"，还是"能等多久"。追求快速致富会导致过度杠杆和情绪化决策。
- **ce24 - 学术策略的局限性**: 学术策略往往过于复杂，超出普通交易者的编程水平约束。

### 作者的盲点 / 时代局限

来自 BOOK_OVERVIEW.md 的批判：

1. **2009年的工具建议已过时**: 书中推荐Excel/MATLAB/TradeStation，但2025年Python生态（pandas、backtrader、zipline）已成为主流。编程水平的定义随工具演进而变化。
2. **忽视了策略学习的曲线效应**: 编程水平不是固定的，用户可以通过学习提升。框架假设约束是静态的，但实际是动态的。
3. **未考虑合作与外包**: 框架假设个人独立完成所有工作，但现实中可以通过合作（编程高手+策略高手）或外包（使用第三方平台）突破约束。

### 容易混淆的邻近方法论

- **约束 ≠ 限制**: 约束是筛选器，帮你聚焦；限制是障碍，让你放弃。约束是积极的，限制是消极的。
- **四要素 ≠ 全部要素**: 四要素是核心要素，但不是全部。还有风险承受力、心理承受力、兴趣偏好等其他要素。
