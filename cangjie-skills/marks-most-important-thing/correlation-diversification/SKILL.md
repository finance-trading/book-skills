# 相关性分散

## R — 原文 (Reading)

> 有效分散風險不是持有很多標的，而是持有的投資組合能在各種環境中做出不同的反應。
>
> — 霍華·馬克斯，第7、17、18、21章

## I — 方法论骨架 (Interpretation)

分散的目标不是让持仓清单变长，而是降低同一错误对组合的共同伤害。
先识别每项资产的主要收益来源、损失机制、融资来源和流动性依赖。
再问这些暴露在利率、信用收缩、恐慌和强平环境中是否会同时恶化。
名义上不同的资产，如果依赖同一因子、资金或交易对手，仍可能是同一笔风险。
真正的分散要求组合在重要压力情境下有不同反应，并保留足够行动能力。
分散也不能替代理解；持有过多无法分析的资产会制造新的盲点。

## A1 — 书中的应用 (Past Application)

### 案例 1: 次级贷款传染到贝尔斯登基金
- **问题**: 次级贷款违约并未停留在原始贷款，而是扩散到 CDO、退休基金和贝尔斯登基金。
- **方法论的使用**: 沿着共同风险来源和流动性链检查不同产品之间的真实关联。
- **结论**: 产品名称不同不代表损失机制不同，分散必须看压力期反应。
- **结果**: 局部违约通过结构化产品和资金链扩散成更广泛的损失。

### 案例 2: 雷曼破产后的危机扩散
- **问题**: 抵押贷款市场崩盘继续影响货币市场、投行和汽车企业。
- **方法论的使用**: 不只分析单一资产的直接风险，追踪市场、融资与实体部门的传染路径。
- **结论**: 组合中看似不同的资产可能共享同一宏观和流动性脆弱点。
- **结果**: 危机扩散到雷曼、贝尔斯登、美林和汽车企业，多个部门同时承压。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户以持仓数量、行业数量或产品名称数量证明组合已经分散。
2. 用户持有多类资产，却担心利率、信用或流动性冲击会让它们一起下跌。
3. 用户需要在建仓前识别共同因子、共同融资来源和压力期相关性。

### 语言信号 (用户的话里出现这些就应激活)

- “我有 50 个标的，够分散了吗？”
- “这些资产相关性 / correlation 会不会在危机时升高？”
- “帮我做组合压力测试 / portfolio stress test。”
- “看起来不同，为什么还会一起跌？”

### 与相邻 skill 的区分

- 与 `defensive-investing` 的区别: 本 skill 专门诊断组合共同暴露；后者决定整体防守目标和结构。
- 与 `permanent-loss-risk` 的区别: 本 skill 关注多个持仓如何共同受损；后者可以单独评估一项资产的永久损失路径。
- 与 `margin-of-safety` 的区别: 本 skill 通过不同反应建立组合缓冲；后者还包括价格、杠杆和仓位缓冲。

## E — 可执行步骤 (Execution)

当 skill 被激活后，agent 应按以下步骤执行:

1. **拆解每项持仓的风险来源**
   - 完成标准: 为每项资产标注主要收益因子、融资来源、流动性依赖、期限和潜在损失机制。

2. **建立压力情境矩阵**
   - 完成标准: 至少测试利率冲击、信用收缩、市场恐慌和流动性中断，判断哪些持仓会同时恶化。
   - 判停条件: 若大部分资产在同一情境下同向损失，不能把持仓数量称为有效分散。

3. **调整共同暴露**
   - 完成标准: 降低重复因子、共同融资和同一流动性来源的集中度，并保留能在压力期有不同反应的资产或现金。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户只要求增加更多证券，不愿提供持仓的风险来源或压力假设。
- 只评估单一资产是否会永久损失，不涉及组合共同反应。

### 作者在书中警告的失败模式

- 买进五十档相关证券却误以为已经分散。
- 只统计持仓数量，不做共同压力测试。
- 用分散数量掩盖共同杠杆、共同流动性或共同宏观暴露。

### 作者的盲点 / 时代局限

- 相关性在危机中的变化难以稳定估计，历史相关性不能保证未来分散效果。
- 书中对跨资产组合的具体统计方法较少，实际应用仍需结合数据和资产结构。

### 容易混淆的邻近方法论

- 持仓数量多不等于分散，资产类别名称不同也不等于风险来源不同。
- 分散不能消除所有风险；它降低的是单一判断或共同冲击对组合的破坏。
