# 大模型能力分级应用指南

## R — 原文 (Reading)

> 从表 2.2 来看，对大模型的使用能力分为九大段位，分别是：无畏玄铁、
> 倔强青铜、秩序白银、荣耀黄金、尊贵铂金、永恒钻石、至尊星耀、最强
> 王者、荣耀王者。这九大段位不仅象征着使用者掌握大模型的深度与广度，
> 也代表了不同场景下大模型的可用能力。
>
> 各个段位的核心要素如下：提示词的优化：能否精准编写引导模型生成优
> 质输出的提示词。数据的利用：能否结合公共数据与私有数据。RAG：是否
> 具备检索增强生成能力。工作流的复杂度：能否利用模型完成复杂的生产
> 流程。
>
> — 罗勇 等, 第2章 2.1.3节

> 推理模型和非推理模型的核心区别：推理模型能够进行多步逻辑推理，在
> 复杂任务中表现更好；非推理模型擅长模式匹配和文本生成，在简单任务
> 中效率更高。
>
> — 罗勇 等, 第2章 2.1.2节

## I — 方法论骨架 (Interpretation)

本书提出了一个大模型能力分级框架，帮助用户匹配任务难度与模型能力：

**九大段位体系**（从低到高）：
- 玄铁/青铜：基础对话，简单问答
- 白银/黄金：提示词优化，基础数据分析
- 铂金/钻石：数据融合（公共+私有），RAG 检索增强
- 星耀/王者：复杂工作流，多步任务自动化
- 荣耀王者：全流程 AI 驱动的生产系统

**推理模型 vs 非推理模型**：推理模型（如 DeepSeek-R1、o1）能做多步逻辑推理，适合复杂量化分析；非推理模型（如 GPT-4、Claude）擅长模式匹配和文本生成，适合数据解析和报告撰写。选择取决于任务复杂度。

**能力评估维度**：提示词优化能力、数据利用能力、RAG 能力、工作流复杂度。用户的段位取决于这四个维度的综合水平。

**核心洞察**：从"玄铁"到"王者"，是从"仅使用模型基础功能"到"深度定制、场景化应用"的能力跃迁过程。

## A1 — 书中的应用 (Past Application)

### 案例 1: 段位能力详解 — 无畏玄铁（入门级）
- **问题**: 初学者如何开始使用大模型
- **方法论的使用**: 仅使用基础功能，依赖默认设置，适合小型文字生成任务、简单问答
- **结论**: 入门用户应从简单任务开始，逐步提升提示词技巧
- **结果**: 形成了段位提升的学习路径

### 案例 2: 段位能力详解 — 尊贵铂金（进阶级）
- **问题**: 如何提升大模型在量化研究中的能力
- **方法论的使用**: 掌握 RAG 技术，结合公共数据与私有数据，能完成中等复杂度的分析任务
- **结论**: RAG 是能力跃迁的关键节点
- **结果**: 用户能构建带知识库的量化分析助手

### 案例 3: 段位能力详解 — 最强王者（专家级）
- **问题**: 如何构建全流程 AI 驱动的量化系统
- **方法论的使用**: 深度定制模型，构建复杂工作流，多模型协作，自动化从数据到交易的全流程
- **结论**: 最高段位需要提示词工程、数据工程、系统架构的综合能力
- **结果**: 形成了完整的 AI 量化交易系统架构

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户不确定自己的量化任务该用什么级别的大模型
2. 用户想了解大模型能力分级，评估自己的使用水平
3. 用户要在推理模型和非推理模型之间做选择
4. 用户要规划大模型能力的提升路径
5. 用户要评估某个量化任务是否适合用大模型完成

### 语言信号

- "用什么大模型" / "which LLM to use"
- "模型能力" / "model capability"
- "推理模型" / "reasoning model"
- "大模型段位" / "LLM tier"
- "DeepSeek vs GPT"
- "这个任务大模型能做吗"
- "能力提升路径"

### 与相邻 skill 的区分 (定稿)

- 与 `prompt-engineering` 的分工: 本 skill 关注**模型选型与能力评估**（选哪个大模型、任务适合什么级别的模型、推理模型 vs 非推理模型），prompt-engineering 关注**模型使用**（如何写 prompt 让选定的模型输出高质量结果）。**先选模型（本 skill）→再写 prompt（prompt-engineering）**——顺序不能反
- 与 `strategy-decision` 的区分: 两者都是"决策类"skill，但决策对象不同——本 skill 评估 **AI 工具能力**（这个任务大模型能做吗、需要哪个级别的模型），strategy-decision 评估 **交易策略类型**（该做阿尔法量化还是贝塔量化）。两者是"工具决策"vs"交易决策"的平行问题
- 与 `mcp-toolchain` 的关系: 本 skill 是 mcp-toolchain 的**前置决策**——先确定用哪个级别的模型（本 skill），再搭建该模型与外部工具的连接（mcp-toolchain）

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **评估任务复杂度**
   - 简单任务：问答、摘要、翻译 → 玄铁-白银
   - 中等任务：数据分析、报告生成、基础因子计算 → 黄金-铂金
   - 复杂任务：多步推理、RAG、工作流自动化 → 钻石-星耀
   - 极复杂任务：全流程 AI 系统、多 Agent 协作 → 王者
   - 完成标准: 已确定任务复杂度等级

2. **选择模型类型**
   - 需要多步逻辑推理 → 推理模型（DeepSeek-R1、o1）
   - 需要文本生成/模式匹配 → 非推理模型（GPT-4、Claude）
   - 需要代码生成 → 代码能力强的模型
   - 完成标准: 已确定模型类型

3. **评估用户当前段位**
   - 提示词优化能力：能否写出结构化 prompt
   - 数据利用能力：能否结合公共+私有数据
   - RAG 能力：能否构建检索增强系统
   - 工作流能力：能否自动化复杂流程
   - 完成标准: 已评估用户段位

4. **给出提升建议**
   - 根据当前段位和目标段位，给出提升路径
   - 推荐学习资源（提示词框架、RAG 技术、Agent 开发）
   - 完成标准: 用户得到清晰的提升方向

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户只需要知道某个具体模型的价格/API —— 这不是能力评估问题
- 用户在做模型微调/蒸馏 —— 这是模型开发，不是模型选择
- 用户的任务不需要大模型（纯规则系统就够了）

### 作者在书中警告的失败模式

- **常见误区**: 认为大模型"什么都能做"—— 实际上每类模型有明确的能力边界
- **过度依赖**: 把不适合大模型的任务（如精确数值计算）交给大模型
- **忽视成本**: 高级模型（推理模型）的 token 成本远高于基础模型
- **版本焦虑**: 模型迭代极快，今天的最优选择明天可能过时

### 作者的盲点 / 时代局限

- 九大段位体系是作者的原创分类，业界并无标准对应
- 书中模型推荐基于 2025 年状态，新模型可能改变格局
- "智力平权"的愿景可能过于乐观——大模型使用仍有技术门槛
- 未讨论开源模型 vs 闭源模型在量化场景的优劣

### 容易混淆的邻近方法论

- 模型基准测试（benchmark）—— 本 skill 是从用户能力角度分级，不是模型性能排名
- 模型微调 —— 本 skill 是选择现成模型，微调是定制模型
