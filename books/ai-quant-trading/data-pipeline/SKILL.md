# 量化交易数据获取与预处理流水线

## R — 原文 (Reading)

> 量化交易策略的开发离不开高质量的数据。数据获取与预处理是量化策略
> 开发的第一步，也是至关重要的一步。数据质量直接决定了后续因子构建、
> 模型训练和策略回测的效果。
>
> — 罗勇 等, 第3章 3.1节

> 通过 API 接入实时市场数据；模型调用历史数据，生成交易信号；人类交
> 易员通过 Slack 接收信号内容，最终执行交易。
>
> — 罗勇 等, 第2章 2.1节 (AI 驱动的因子挖掘与信号发现)

---

## I — 方法论骨架 (Interpretation)

本书提出了一个完整的数据流水线方法论：

**数据源分层**: 行情数据（AKShare/Tushare/Wind）、财务数据（东方财富/同花顺）、另类数据（研报 PDF、新闻、社交媒体）。不同策略需要不同数据源组合。

**获取→清洗→特征构造三步流水线**:
1. **获取**: 通过 API 批量下载，处理限流、断点续传、数据完整性校验
2. **清洗**: 去重、缺失值填充（前向填充/插值）、异常值检测（3σ/分位数）、复权处理
3. **特征构造**: 从原始数据计算技术指标、量价特征、时间特征，为因子挖掘做准备

**数据质量保障**: 书中强调要评估不同数据源的覆盖度、时效性、准确性，制定数据质量保障方案。实盘环境下要应对数据延迟、异常、漂移等问题。

**大模型辅助**: 用大模型自动化数据获取脚本生成、清洗规则设计、异常数据标注。

## A1 — 书中的应用 (Past Application)

### 案例 1: AKShare/Tushare 数据获取与清洗
- **问题**: 需要获取 A 股日线行情和财务数据用于策略开发
- **方法论的使用**: 用 AKShare 获取日线行情（开盘/收盘/最高/最低/成交量/成交额），用 Tushare 获取财务指标数据；清洗时处理停牌日缺失值、除权除息复权
- **结论**: 建立了标准化的数据获取与清洗流程
- **结果**: 形成可复用的数据获取代码模板

### 案例 2: 研报与舆情数据自动化采集
- **问题**: 需要从券商研报和财经新闻中提取结构化信息
- **方法论的使用**: 设计自动化采集流程——爬取研报 PDF → OCR/文本提取 → 大模型解析关键信息（目标价、评级、因子）→ 结构化存储
- **结论**: 大模型能高效处理非结构化金融文本
- **结果**: 实现了从研报到因子数据的自动化转换

### 案例 3: 实盘数据质量问题处理
- **问题**: 实盘环境中数据延迟、异常、漂移影响策略稳定性
- **方法论的使用**: 设计数据监控方案——实时校验数据完整性、检测异常值、处理数据漂移
- **结论**: 数据质量保障是实盘策略稳定运行的前提
- **结果**: 建立了数据质量监控与报警机制

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. 用户刚开始做量化交易，需要搭建数据基础设施
2. 用户要从特定数据源（AKShare/Tushare/Wind）获取数据但遇到 API 限制或数据质量问题
3. 用户需要设计数据清洗方案处理缺失值、异常值、复权等问题
4. 用户要评估不同数据源的优缺点，选择最适合的数据方案
5. 用户需要为实盘策略构建数据质量监控体系

### 语言信号

- "数据获取" / "data fetching"
- "数据清洗" / "data cleaning"
- "AKShare" / "Tushare" / "Wind"
- "数据预处理" / "data preprocessing"
- "缺失值" / "missing data"
- "复权" / "adjustment"
- "数据质量" / "data quality"

### 与相邻 skill 的区分 (定稿)

- 与 `factor-mining` 的分工: 本 skill 是**数据工程层**（获取/清洗/存储/质量监控），factor-mining 是**因子方法论层**（挖掘/验证/迭代）。本 skill 是 factor-mining 的**前置条件**——没有干净的数据就没有有效因子。当你问"怎么从 Tushare 拿数据并处理缺失值"→本 skill；问"怎么从这些数据里挖出有效 alpha"→factor-mining
- 与 `mcp-toolchain` 的对比: 两者都是"让大模型接入外部能力"的方法，但**抽象层次不同**。本 skill 是传统数据工程（Python API 调用 + ETL 流水线），mcp-toolchain 是 Agent 架构（MCP 协议 + 工具注册）。当任务可以写死脚本时用本 skill；当需要大模型**动态决策**调什么工具时用 mcp-toolchain
- 与 `sentiment-quant` 的关系: 本 skill 提供舆情数据的**采集与清洗**流水线，sentiment-quant 提供基于这些数据的**情绪评分与事件驱动**方法论。两者是上下游关系

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **评估数据需求，选择数据源**
   - 明确策略需要的数据类型（行情/财务/另类）
   - 评估数据源：覆盖度、时效性、成本、API 限制
   - 推荐组合：AKShare（免费行情）+ Tushare（财务）+ 爬虫（另类）
   - 完成标准: 已确定数据源方案

2. **构建数据获取脚本**
   - 编写 API 调用代码，处理限流和断点续传
   - 实现数据完整性校验（日期连续性、字段完整性）
   - 完成标准: 数据获取脚本可稳定运行
   - 判停条件: 若 API 限流严重 → 考虑本地缓存或付费数据源

3. **设计数据清洗方案**
   - 缺失值处理：停牌日（前向填充）、财务数据（插值）
   - 异常值检测：3σ 法则 / 分位数法 / 业务规则
   - 复权处理：前复权/后复权选择
   - 完成标准: 清洗后的数据质量达标

4. **特征构造**
   - 从清洗后的数据计算技术指标（MA/RSI/MACD 等）
   - 构造量价特征（换手率、振幅、量比等）
   - 构造时间特征（星期、月份、节假日）
   - 完成标准: 特征数据可供因子挖掘使用

5. **数据质量监控（实盘场景）**
   - 实时监控数据延迟
   - 自动检测异常值和数据漂移
   - 建立报警机制
   - 完成标准: 监控系统上线运行

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- 用户只需要简单的股价查询（用 `yfinance` 一行代码搞定）—— 不需要完整流水线
- 用户的任务纯是因子挖掘或策略设计 —— 用 `factor-mining` 或 `strategy-decision`
- 用户在做非量化领域的数据工程 —— 本 skill 专门面向量化交易数据

### 作者在书中警告的失败模式

- **数据延迟**: 实盘中数据延迟会导致信号滞后，策略失效
- **数据漂移**: 数据分布随时间变化，历史清洗规则可能不再适用
- **数据源依赖**: 过度依赖单一数据源，一旦 API 变更策略瘫痪
- **复权错误**: 复权处理不当会导致回测结果严重失真

### 作者的盲点 / 时代局限

- 书中数据源推荐基于 2025 年状态，API 和政策可能已变化
- 未充分讨论数据成本问题（Wind 等专业数据源费用较高）
- 对数据合规性（爬虫合法性、数据使用授权）讨论不足

### 容易混淆的邻近方法论

- 通用 ETL/数据工程 —— 本 skill 专门面向量化交易的数据特点（复权、停牌、高频等）
- 特征工程 —— 本 skill 包含特征构造步骤，但特征工程的深度方法在 `factor-mining` 中
