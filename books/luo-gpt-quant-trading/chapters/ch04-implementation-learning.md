# 第4章：量化交易策略的代码开发与实战

## 核心思想

开发路径应由策略逻辑、复杂度和可执行要求决定。低代码适合快速表达常见规则；复杂套利、对冲、高频和定制化研究需要高级语言、数据治理与更严格工程控制。编码只是研究链路的一环。

## 开发路径选择

| 路径 | 适用情形 | 主要限制 |
|---|---|---|
| 低代码/平台模块 | 常见趋势、反趋势、筛选、模拟验证；降低入门成本 | 函数与数据受平台限制，复杂逻辑和可移植性不足 |
| 高级语言 | 复杂策略、定制因子、跨资产/数据处理、研究复现 | 需要编程、测试、数据与运行维护能力 |
| 机器学习 | 有充分数据、明确任务和验证设计，模型能解决传统方法难处理的问题 | 更易过拟合；解释、漂移、标签泄漏和实盘部署成本更高 |

## 实践步骤

1. **写规则**：明确证券池、信号、调仓、仓位、风险、基准和退出条件。
2. **选择平台**：先判断表达能力、数据质量、回测假设、费用模型和导出/审计能力，再选语言。
3. **实现最小版本**：把逻辑拆为数据输入、信号计算、组合构建、交易模拟和绩效报告；每层检查时间对齐与单位。
4. **验证数据与订单**：处理复权、停牌、涨跌停、合约换月、交易时段、滑点和费用，避免理想化成交。
5. **评估样本外**：先训练/研究，再用未参与调参的数据验证；机器学习任务还需避免标签泄漏、类别失衡和时间序列随机打乱。
6. **逐步部署**：从离线回测到纸面/模拟，再到小规模实盘；监控信号、订单、成交和风险偏离。

## 书中案例可复用的教训

- 多因子选股、CTA、基金 FoF 等例子展示了同一框架如何映射到不同资产与信号，不代表这些案例的参数或业绩可直接复制。
- 经典模型改进应有明确的机制依据。不断增加条件直到历史收益变好，会把研究者的选择偏差编码进策略。
- 低代码降低表达门槛，但不会替代对金融逻辑、数据时点和成交约束的理解。

## 盘口执行示例

书中用做市/高频示例说明执行层的双面性：在稀疏盘口两侧挂单可赚价差，但单边成交后价格可能向不利方向移动。示例的盘口不平衡指标以一档买卖量给更高权重，再用阈值作为短期方向开关。其教学重点是把订单簿数据、方向预测和执行风险连起来；没有低延迟数据、成交模拟和库存/单边风险控制时，不应把示例直接部署。

## 代码/公式示例：盘口不平衡

书中做市案例用盘口前两档买卖量构造短期方向指标，给一档更高权重：

```python
OBS = (2 * (df["bv1"] - df["av1"]) + (df["bv2"] - df["av2"])) / 3 / (df["av1"] + df["bv1"] + df["av2"] + df["bv2"])
```

这只是研究示例，不是可直接下单的策略：先处理涨跌停时缺失/为零的盘口、盘口归一化、时间戳、成交延迟、库存和单边成交风险，再以模拟成交验证阈值。

## 机器学习定位

书中覆盖监督学习、无监督学习与深度学习在量化中的基本用途。实际使用时先定义任务：监督学习预测已有标签，无监督学习探索结构，深度学习表达复杂函数关系。模型比较必须使用符合时间顺序的验证、成本后策略结果和稳定性；模型指标改善不自动意味着可交易收益改善。复杂模型只有在相对于简单基准的增量价值覆盖成本与风险时才值得部署。

## 反模式

- 在图表或平台中看到漂亮回测就跳过数据和交易假设审计。
- 把训练集表现、分类准确率或单次回测收益当成实盘优势。
- 对经典策略连续调参，却不保留未触碰的验证集。
- 让 GPT 生成的程序未经阅读、测试和安全审查直接连接真实账户。

## 实践例子

将“多因子选股”先写为无代码规范：数据截点、因子方向、缺失值规则、股票池、排序方式、行业约束、调仓日和成本模型。再选择能忠实实现这些要求的平台，用小规模样本逐项核对中间结果；确认无前视后进行样本外测试。该规范比代码本身更适合作为跨工具复现依据。

## 行动要点

1. 先选可解释的最简单实现，再证明复杂化的边际收益。
2. 代码与数据时间戳必须和决策时点一致。
3. 把成本、成交限制和运行监控当作策略定义的一部分。
4. GPT 生成代码只作草稿；人工复核逻辑、API、数据泄漏与订单边界。
