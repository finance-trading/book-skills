# 模型风险的三种来源分类

## R — 原文

> "模型风险来自许多方面，最常见的是模型的不适宜性、模型的错误设定以及执行错误。"
>
> — Rishi Narang, 第10章

---

## I — 方法论骨架

模型风险来自三个来源，每种有不同的应对方法：

**来源1：模型的不适宜性（Inappropriateness）**
- 模型无法准确描述现实
- 过度简化复杂现象
- 假设条件不成立
- 例：用线性模型描述非线性关系；假设数据服从正态分布但实际呈现厚尾特征

**应对方法**:
- 压力测试：模拟不同市场情况
- 模型验证：检验模型假设是否成立
- 持续监控：识别模型失效的信号

**来源2：模型的错误设定（Misspecification）**
- 模型正确但参数设定不当
- 例：VaR的置信水平设定过低；波动率窗口选择不当

**应对方法**:
- 参数敏感性分析：测试不同参数下的表现
- 稳健性检验：确保结果对参数变化不敏感
- 定期校准：根据市场变化调整参数

**来源3：执行错误（Implementation Error）**
- 程序bug、数据错误、系统故障
- 例：骑士资本30分钟损失4.4亿美元；法国安盛风险模型代码错误导致2.17亿美元损失

**应对方法**:
- 严格的测试流程：单元测试、集成测试、压力测试
- 实时监控：识别异常交易行为
- 应急预案：快速停止交易的"杀死开关"

**三种来源的关系**
- 不适宜性是理论基础问题
- 错误设定是参数问题
- 执行错误是实施问题
- 三者可能同时存在，需要综合考虑

## A1 — 书中的应用

### 案例1: LTCM的模型不适宜性
- **问题**: LTCM假设市场关系稳定，忽略极端事件
- **方法论的使用**: 模型无法描述极端市场情况
- **结论**: 模型不适宜性导致在1998年俄罗斯危机中失效
- **结果**: 需要美联储组织华尔街银行救助

### 案例2: VaR模型的错误设定
- **问题**: 传统VaR假设正态分布，低估极端风险
- **方法论的使用**: 参数设定不当（置信水平过低）
- **结论**: 4σ事件实际频率比正态分布预测高118倍
- **结果**: 许多机构在2008年金融危机中因VaR失效而遭受巨大损失

### 案例3: 骑士资本的执行错误
- **问题**: 软件bug导致发送大量错误订单
- **方法论的使用**: 缺乏有效的测试和监控
- **结论**: 执行错误在30分钟内导致4.4亿美元损失
- **结果**: 公司几乎破产

### 案例4: 法国安盛的执行错误
- **问题**: 风险模型代码错误持续2年多才被发现
- **方法论的使用**: 缺乏有效的验证和监控机制
- **结论**: 执行错误导致客户损失2.17亿美元
- **结果**: 公司声誉严重受损，管理资产从620亿美元下降到180亿美元

## A2 — 触发场景

### 用户会在什么情境下需要这个skill?

1. 诊断策略失效的原因时
2. 评估新策略的模型风险时
3. 设计模型风险控制措施时
4. 比较不同策略的模型风险时
5. 向他人解释策略风险时

### 语言信号

- "这个策略有什么风险？"
- "策略失效了怎么办？"
- "如何评估模型风险？"
- "模型准吗？"
- "代码有bug怎么办？"

### 与相邻skill的区分

- 与 `fat-tail-principle` 的区别: 本skill识别所有模型风险来源，fat-tail-principle专注厚尾风险
- 与 `historical-data-limitation` 的区别: 本skill识别模型风险来源，historical-data-limitation讨论历史数据局限
- 与 `risk-management-two-dimensions` 的区别: 本skill识别模型风险，risk-management-two-dimensions控制市场风险
- 与 `research-scientific-method` 的区别: 本skill识别模型风险，research-scientific-method避免模型风险

## E — 可执行步骤

1. **识别模型风险的三种来源**
   - 完成标准: 明确当前策略面临的模型风险来自哪个来源
   - 判停条件: 若三个来源都需要考虑，分别处理

2. **评估不适宜性风险**
   - 完成标准: 评估模型是否能准确描述现实
   - 具体步骤:
     - 检验模型假设是否成立
     - 压力测试：模拟不同市场情况
     - 持续监控：识别模型失效的信号

3. **评估错误设定风险**
   - 完成标准: 评估参数设定是否恰当
   - 具体步骤:
     - 参数敏感性分析
     - 稳健性检验
     - 定期校准参数

4. **评估执行错误风险**
   - 完成标准: 评估实施过程是否可靠
   - 具体步骤:
     - 严格的测试流程
     - 实时监控
     - 应急预案

5. **提供改进建议**
   - 完成标准: 针对每种来源提出具体的控制措施
   - 判停条件: 若模型风险已有效控制，跳过此步骤

## B — 边界

### 不要在以下情况使用此skill

- **非模型化的交易策略**: 如主观判断型交易，不使用量化模型
- **不涉及模型风险的其他类型风险**: 如市场风险、流动性风险、操作风险（虽然执行错误是操作风险的一部分，但本skill专注模型风险）
- **纯理论分析**: 如经济学理论研究，不涉及实际模型实施

### 作者在书中警告的失败模式

- **忽视模型不适宜性**: 假设模型能准确描述现实
- **参数设定不当**: 如VaR置信水平过低
- **执行错误**: 如骑士资本的软件bug
- **缺乏监控**: 如法国安盛的代码错误持续2年多才被发现

### 作者的盲点/时代局限

- **出版于2016年**: 书中对现代机器学习模型的模型风险讨论较少
- **美国中心视角**: 案例主要来自美国市场
- **缺乏具体工具**: 书中提供方法论框架，但没有具体的测试工具推荐

### 容易混淆的邻近方法论

- **与"市场风险"混淆**: 市场风险是外部因素，模型风险是内部因素
- **与"操作风险"混淆**: 操作风险包括执行错误，但模型风险更广泛
- **与"过拟合"混淆**: 过拟合是模型错误设定的一种表现，不是全部
