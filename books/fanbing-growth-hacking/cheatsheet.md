# 增长黑客决策速查

## 判断规则

| 情况 | 该做什么 | 原因 |
|---|---|---|
| 产品次日/7日留存差 | 先修 PMF，暂停大规模获客 | 留存是价值假设的检验，获客只会放大失败 |
| 不确定该做什么功能 | 先问“哪个动作完成率低” | 瓶颈在激活，不在更多功能 |
| 两个方案难判优劣 | 做单变量 A/B 测试 | 数据替代争论；结论要注明场景 |
| 新用户注册后无事可做 | 在注册末尾推荐关注/订阅/首个任务 | 让时间轴有内容，降低流失 |
| 高峰弱网/低端设备 | 有损降级：保核心，牺牲非核心 | 可用性优先于完整性 |
| 免费用户占 90%+，付费率 <2% | 考虑取消免费或提高免费门槛 | 免费成本失控，转化不足 |
| 用户已付费/盗版但被要求停用 | 用补偿+便利转化，不责备 | 封杀把用户变敌人 |
| 病毒活动爆发前 | 先定服务器容量、客服、停止条件与隐私边界 | 传播越快，故障与合规风险越大 |
| 邀请推荐只带来低留存用户 | 优化落地页与被推荐者体验，不是更多奖励 | 推荐量不等于增长质量 |
| 渠道曝光高但转化低 | 检查落地页、加载速度、信任信号 | 转化瓶颈常在接收端 |
| 指标定义不一致 | 先对齐“活跃/转化/留存”口径与上报机制 | 指标是团队共识，不是数字游戏 |

## 决策树

1. 产品达到 PMF 了吗？未达 → 用 MVP 迭代，不推大规模获客。
2. 已达 PMF，瓶颈在哪一层 AARRR？
   - 获取 → 种子用户 / 内容 / 社交平台 / SEO / ASO。
   - 激活 → 降低关键动作门槛 / A/B / 游戏化 / 补贴。
   - 留存 → 性能、有损服务、引导、社交维系、唤醒机制。
   - 收入 → Freemium、交叉补贴、广告、重定向、推荐计划。
   - 传播 → K 因子、循环周期、内置因子、体外循环。
3. 每个实验是否单变量、有指标、可归因、有停止条件？
4. 增长手段是否越过隐私、授权、平台规则与诚信边界？越界 → 停止。

## 关键阈值与经验值

- 电商留存 20%–30% 可活；社交媒体首批月留存 <80% 难做大。
- Facebook 平台游戏 40-20-10 规则：次日 >40%、7日 >20%、30日 >10%，DAU 才有百万可能。
- K 因子 >1 才有自我传播；感染率与转化率都可优化。
- 重定向广告 30 天内 7–10 次曝光转化最佳。
- 每月优化 10%，一年约 3 倍提升（复利思想）。
- 推送：开启用户数月后再次使用率 62%，关闭后仅 32%。
- 23% 用户曾因推送卸载应用；推送要分群分时。
- 网站打开每慢 100ms，损失约 100 万美元营收（亚马逊口径）。
- 免费转付费率极低（如 0.8%）说明免费层设计有问题。
- A/B 测试中约 1/3 有效（微软经验），产品不息，测试不止。

## 危险信号（Tells）

- 总量增长但活跃/收入不涨 → 漏损或虚荣指标。
- 新增猛增、留存跳水 → 获客渠道质量问题。
- 只谈功能不谈数据 → 团队缺数据共识。
- 补贴一停用户就停 → 没有建立习惯。
- 游戏化很热闹、核心任务完成率低 → 本末倒置。
- 推荐活动带来大量“薅羊毛”用户、3日活跃低 → 奖励吸引错的人。
- 增长手段依赖灰色/隐私越界 → 短期有效、长期致命。
- 指标好看但没有对应行动项 → 看板只是装饰。

## 一句话心法

- 增长是“假设—实验—数据—决策”的循环，不是渠道堆砌。
- 先修漏斗底（留存），再开进水口（获客）。
- 用最少步骤完成关键动作，用最少授权获取最大信任。
- 传播要给用户真实动机，不要用强迫与欺骗。
- 指标要回答“接下来做什么”，而不是“过去多好看”。
