# Chapter 8: Pivot (or Persevere)

## Core Idea
Pivot 是“一个脚着地”的结构性改变：保留已学到的，改变关于产品、商业模式或增长引擎的根本假设。当调优不再带来进展时，应启动 pivot 讨论，而非继续硬推。

## Frameworks Introduced
- **Pivot-or-persevere 决策**：以创新会计的学习里程碑为输入，评估是否继续当前战略或转向新的战略假设。
  - How：① 定期召开 pivot-or-persevere 会议（几周一次太频繁、几个月一次太稀疏）；② 产品团队报告完整调优历史与预期对比；③ 业务团队报告客户访谈；④ 对照 learning milestones 判断；⑤ 若转 pivot，明确保留什么、改变什么、新的根本假设是什么；⑥ 为新假设设计新的 MVP。
  - 成功的 pivot 标志：pivot 后实验比 pivot 前更有效，MVP 周期越来越短（Votizen 从 8 个月到 1 个月）。
- **Runway 重定义**：不是剩余现金月数，而是还能完成多少次 pivot。越能低成本/短时间跑完 Build-Measure-Learn，越能延长 runway；盲目裁成本可能砍掉的就是跑循环的能力。
- **Pivot 类型目录**：zoom-in / zoom-out、customer segment、customer need、platform、business architecture、value capture、engine of growth、channel、technology。每一种都是“新的战略假设 + 新 MVP”，不是任意“改变”。

## Key Concepts
- **Living dead**：有少量收入与增长、但无法形成可持续业务；因沉没成本而长期拖延 pivot。
- **Strategic hypothesis**：pivot 是新的战略假设，需要新的 MVP 与测试，不是单纯的“改变”。
- **成功后的 complacency**：早期成功会让团队迷信“你不能与成功争论”，忽略客户群变化（IMVU 从早期采用者转向主流客户时的失败）。

## Mental Models
- 若增长指标长期停滞或下降，优先怀疑战略假设，而非执行细节。
- 成功早期采用者并不保证主流客户成功；customer segment pivot 往往需要在质量、服务与渠道上重新投入。
- Pivot 的产出是“更快、更便宜”的下一轮学习，不是更大更强的旧版本。

## Anti-patterns
- 把 pivot 当作失败，或当作无限次“小调整”的借口。
- 用总量上升的 vanity metrics 掩盖学习停滞。
- 在没有明确假设时“launch and see”，永远无法获得失败证据。
- 成功让团队迷信“你不能与成功争论”，忽略客户群变化。
- pivot 时把所有已建工作扔掉，而非保留仍有效的部分（技术、客户关系、渠道）。

## Worked Example
Votizen 最初是“已认证投票人的公民社交网络”，registration 与 activation 优化后仍停留在 5–8% 的 retention 与 referral，无法支撑增长。David 连续三次 pivot：zoom-in 到 @2gov 社会游说，再 customer segment 转向 B2B，最后 platform pivot 做自助平台；每轮 MVP 时间从 8 个月缩短到 1 个月，最终 referral 达 64%、LTV 为每信息 $0.20。

## Key Takeaways
1. 定期召开 pivot-or-persevere 会议，带完整学习数据与客户访谈。
2. 把 runway 定义为可完成 pivot 次数，追求更短更便宜的 MVP。
3. 每个 pivot 明确新的根本假设，并设计对应 MVP。
4. 警惕“成功”带来的 complacency，尤其 customer segment pivot。
5. Pivot 时保留仍有效的技术、关系与渠道，而非全部推倒。
