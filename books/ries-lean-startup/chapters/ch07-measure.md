# Chapter 7: Measure

## Core Idea
初创企业不能用传统财务预测衡量创业团队。Innovation accounting 把 leap-of-faith assumptions 转为可量化的财务与行为模型，用学习里程碑替代固定的产品/收入里程碑，以便客观判断“是否在真正学习”。

## Frameworks Introduced
- **Innovation accounting**：三步——
  ① 用 MVP 建立真实 baseline（哪怕结果很糟）；
  ② 从 baseline 调优 engine of growth，每次针对一个增长驱动因素；
  ③ 若持续调优仍不能让指标向可持续模型靠近，进入 pivot-or-persevere。
  - When to use：有 MVP 与早期客户，需要向团队/投资人证明进展。
  - Why it works：把“我们在努力”转为可比较的因果证据；pivot 后重建 baseline，成功 pivot 的标志是后续实验更有效。
- **Learning milestones**：替代传统产品/销售里程碑的三类证据：baseline、engine tuning、pivot-or-persevere 决策点。
- **Cohort analysis**：按时间分组独立追踪每组客户从接触到行为的路径，而不是看总量。每一组都是独立的“成绩单”。
- **Split test / A-B test**：同一时间向两组客户呈现不同版本，比较行为差异，建立因果推断。

## Key Concepts
- **Vanity metrics**：总量指标（总用户、总收入、总下载），掩盖质量与学习，无法证明可持续业务。
- **Actionable metrics**：能改变行为、可归因、支持决策的指标，通常来自 cohort 或 split-test。
- **Growth drivers**：具体业务的增长引擎变量（留存、获客成本、单位利润、复购等）。
- **Kanban（容量约束）**：用户故事只有经过验证才算“完成”；限制每个阶段的故事数量，防止未验证工作堆积。

## Mental Models
- 先看 cohort 再看总量：总量上升可能来自过去积累，而非当前工作。
- 每项产品/营销工作必须对应一个明确的驱动因素与假设，否则难以判断成败。
- 用“是否能预测结果”判断工作是在学习还是在优化。

## Anti-patterns
- 用总注册、总收入、媒体曝光证明进展。
- 同时上线多项改动，无法判断哪项起效。
- 指标不断换口径，无法追踪因果关系。
- 在“living dead”状态盲目坚持：有些增长、但远不能形成可持续业务。
- 把“优化”误当“学习”：在错误产品上做 A/B 测试，只会更高效地做错事。

## Worked Example
IMVU 早期：尽管每天优化产品，7 个月中 75% 的新注册者至少登录一次，但每个 cohort 的付费比例始终约 1%。Cohort 分析揭示优化无效，团队转而与客户面谈，发现真实需求是“结识新朋友”而非“现有朋友”。pivot 到独立网络后，学习产出显著提高。另一个案例 Grockit 从总用户数转向 cohort + split test，才发现“社交功能越多越好”的假设错误，真正有效的是社交与独自学习的组合。

## Key Takeaways
1. 把每条假设对应到一个可量化的指标，并设定 baseline。
2. 用 cohort 与 split-test 替代总量。
3. 每项工作应映射到明确的增长驱动因素。
4. 指标不能改善时，是启动 pivot-or-persevere 讨论的信号。
5. 用 kanban 限制未验证工作在制品（WIP）。
