# Chapter 11: Adapt

## Core Idea
随公司成长，必须用“按问题比例投资”的自适应流程替代“无流程”或“过度流程”。Five Whys 把技术故障追溯到流程与人，使每次问题都转化为一次可累积的预防投资。

## Frameworks Introduced
- **Adaptive organization**：流程随条件自动调整；速度不是唯一目标，需要内置“调速器”，用问题驱动预防投资。
  - How：① 在问题出现时启动根因分析；② 只做与症状严重度相称的修复；③ 问题复发则继续加深预防；④ 预防见效后自然加速。
- **Five Whys**：连续问五次“为什么”，从症状追溯到根因；在每个层级做与问题严重度成比例的投资。
  - 经典例：机器停转 → 保险丝烧断 → 轴承润滑不足 → 润滑泵抽送不足 → 泵轴磨损 → 没有滤网，金属碎屑进入。根因从技术故障移到“人忘了装滤网”。
  - 软件例：新版本禁用功能 → 服务器故障 → 子系统误用 → 工程师不会用 → 没受过培训 → 经理认为“太忙”不培训。
- **Proportional investment**：小问题做小修复；问题重复出现时，继续投入更深层的预防。不要为一次小故障启动八周大计划，也不要用“换保险丝”应付会复发的根因。

## Key Concepts
- **Five Blames**：把根因分析变成相互指责；根因通常是坏流程，不是坏人。
- **Speed regulator**：问题越多，越投资于预防；预防见效后再加速。
- **Five Whys master**：有足够权限推动改进、主持会议、指派跟进，但不至于忙到无法参会。
- **Andon cord 悖论**：“停止生产，才能让生产永不停止”——不能以质量换时间。

## Mental Models
- 把每个故障视为系统信号：技术问题背后常是培训、流程或管理假设。
- 先用小范围、低风险问题练习 Five Whys，再扩展到高 stakes 领域。
- 修复要“比例适当”，避免为小故障启动庞大计划，也避免重复问题只做表面修补。
- “首次错误宽容，同错不二犯”是低信任环境下的简化替代方案。

## Anti-patterns
- 无流程或一次性引入庞大流程，二者都不可持续。
- 把 Five Whys 变成追责会；遗漏与问题相关的人。
- 以“没时间分析根因”为由跳过预防，导致返工与危机循环。
- 一开始就处理所有历史“baggage”，而非让它们在真实问题中自然浮现。
- 在没有高层支持时由个人推动 Five Whys，容易半途而废。

## Worked Example
QuickBooks 的年度大版本流程：第一年按瀑布式开发在线银行功能，beta 反馈已显示客户不满，但因“技术无缺陷”无法停发；上线后客户对账时间增加 4–5 倍，NPS 下降 20 分，修复又花了 9 个月。第二年只改发布节奏，组织“肌肉记忆”把流程拉回原样。第三年才同时改团队结构（≤5 人跨职能）、缩短周期、让客户从概念阶段参与，并投资虚拟化技术让新版本可在不影响客户数据的前提下测试，最终以小批量发布获得更高满意度与销量。

## Key Takeaways
1. 用 Five Whys 把失败转为流程改进。
2. 首次错误宽容，同错不二犯。
3. 让所有相关方在场，避免 Five Blames。
4. 指定 Five Whys master，并从窄问题开始。
5. 技术修复与组织/培训投资同步进行。
6. 组织有“肌肉记忆”；只改日期不改系统，流程会回弹。
