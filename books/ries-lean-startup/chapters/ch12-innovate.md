# Chapter 12: Innovate

## Core Idea
大组织可以持续创新，但必须同时保护母公司和新创团队：给团队稀缺而安全的资源、独立开发权与个人利害关系，并用“创新沙盒”把实验影响限制在可控范围内。

## Frameworks Introduced
- **三个结构条件**：
  ① **scarce but secure resources**（少但不可被随意削减）：过多预算同样有害，且中途削减是致命打击；
  ② **independent development authority**（跨职能、无需层层审批）：团队必须能构建并发布可运行的产品，handoff 与审批要压到最低；
  ③ **personal stake**（股权、长期激励或明确署名与荣誉）：金融激励不是唯一形式，非营利与政府组织可用署名与荣誉；关键是“门牌上写着谁的名字”。
  - How：① 用独立 P&L 或专项预算隔离资金；② 让产品/工程/市场/客服全程参与；③ 把激励与 3–5 年创新绩效挂钩，而非年度报表。
- **Innovation sandbox**：
  ① 任何团队可在限定范围（功能/客户群/地区）做真实 split test；
  ② 一个团队端到端负责整个实验；
  ③ 实验有时间上限（简单功能数周、颠覆式创新更长）；
  ④ 影响客户数有上限（通常占主流客户基数的固定百分比）；
  ⑤ 统一用 5–10 个 actionable metrics 评估；
  ⑥ 所有沙盒团队与产品共用同一套指标；
  ⑦ 实验期间持续监控客户反应，灾难时中止。
- **Portfolio thinking**：同时管理四类工作——研发/创新、增长（规模化）、优化、legacy/运营成本；产品在不同阶段交接给不同团队，员工可选择跟随产品或留在创新团队。“Entrepreneur”应成为可长期发展的职业路径。

## Key Concepts
- **Shusa（主工程师）**：Toyota 的重型项目负责人，对整车开发拥有最终权威并承担个人责任，是“个人利害关系”的组织样本。
- **Black box 创新**：秘密 skunkworks 可产生一次性成功（IBM PC），但常难持续、易引发政治与不信任；问题在高管未设计支持系统，而不在于被隐瞒的管理者。
- **Innovation accounting 的内部应用**：内部团队同样以 baseline→tune→pivot 的学习里程碑问责。

## Mental Models
- 反转发问：不是“如何保护创新团队免受母公司干扰”，而是“如何保护母公司免受创新团队冲击”。
- 把沙盒想成“有围栏的试验田”：限制影响范围，但不限制实验方法。
- 创新成功后会变成新的 status quo；需要为下一轮创新预留新沙盒。
- 沙盒扩大时，评估团队是否已能在母公司中“自保”，再决定是否撤掉围栏。

## Anti-patterns
- 把创新团队藏起来，导致其他管理者事后被“突袭”并报复。
- 给创新团队过多或随时可被削减的预算。
- 用不透明、主观的奖励分配代替明确产权/署名。
- 让创造者永远跟随产品进入运营阶段，导致创新人才枯竭。
- 用部门各自解释的数据打政治战，而非统一指标与端到端责任。

## Worked Example
某大型软件公司想以降价实验进入消费者市场，但跨部门、长周期、口径不一的“数据驱动”会议最终变成各派解释数据的政治斗争。解法：建立仅覆盖定价页的沙盒，由跨职能团队端到端负责，限定时间与客户比例，统一 5–10 个指标；成功后逐步扩大沙盒范围。

## Key Takeaways
1. 用三个结构条件设计内部创业团队。
2. 用沙盒限制风险并公开实验，而非秘密创新。
3. 以统一指标和学习里程碑问责内部团队。
4. 把“entrepreneur”视为可持续的职业路径与岗位。
5. 创新成功后主动重建新沙盒，避免创新者变成守成者。
6. 四类工作交给不同团队；让优秀管理者不必离开公司就能继续创新。
