## R — 原文

> "可投资性反映在两方面：一是因子建模所使用的数据应当是当前或者历史可观测到的数据。使用未来函数或数据构建因子，可能导致量化交易策略在回测中有效，但对于实盘的应用却毫无意义。"
>
> — §3.1（因子可投资性的基本要求）

## I — 方法论骨架

未来函数偏差（Look-Ahead Bias）是量化回测中最严重也最常见的错误之一，
其机制是：在回测计算中，使用了在实际信号生成时刻（T时）之后才能获得的数据。

常见的未来函数场景：
1. 使用当日收盘价计算因子，然后在当日收盘前发出信号（实盘时收盘价不可知）；
2. 使用财报发布日的数据，但假设在财报发布前就能使用（时间戳错误）；
3. 使用标准化处理后的历史均值（均值本身包含了"未来"数据点）；
4. 在滚动窗口计算中，窗口终点超过信号生成时刻；
5. 使用复权价格（前复权）时，每次发生除权除息都会改变历史所有价格，
   使"历史"价格实际上包含了未来信息。

未来函数的后果是：回测结果看起来极其优秀（因为实际上用了未来信息），
但在实盘中，这些信息不存在，策略表现与回测完全不符，通常导致严重亏损。
这是量化新手"回测完美、实盘亏损"这一普遍现象的最主要原因之一。

核心原则：所有在时刻T用于生成信号的数据，必须在时刻T之前已经可以观测到。

## A1 — 书中应用

书中§3.1在讨论因子的"可投资性"时，将"不使用未来函数"列为第一个基本要求：
作者明确指出：因子建模使用的数据必须是"当前或者历史可观测到的数据"。
若使用未来函数，回测结果会显示因子有效（因为本质上是在用未来信息预测过去），
但在实际部署时，由于未来信息不存在，策略完全失效，"毫无意义"。
书中将此与另一个可投资性要求（考虑实盘约束：交易成本、市场规模等，参见ce20）
并列，作为因子设计的两个最基本的检查维度。
这一警告出现在阿尔法002因子分析之后（参见ce15、ce16），进一步说明了
国外因子移植失败的另一个潜在原因：时间戳处理方式的差异。

## A2 — 触发场景

1. 因子计算中使用了当日收盘价，而策略信号在当日收盘之前生成时触发。
   信号词：close price signal / 收盘价信号、same-day close / 当日收盘。

2. 财务数据的时间戳设置为"报告期末日期"而非"实际发布日期"时触发。
   信号词：report date vs release date / 报告期vs发布日、instant financial data / 即时财务数据。

3. 回测中使用了前复权价格，但没有意识到每次除权都改写了历史价格时触发。
   信号词：backward-adjusted prices / 前复权价格、price restated / 价格重述。

4. 标准化处理（z-score归一化）使用了包含未来数据点的全样本均值时触发。
   信号词：full sample normalization / 全样本归一化、in-sample mean / 样本内均值。

5. 回测结果异常完美（年化收益>50%，最大回撤<5%）但未进行未来函数专项检查时触发。
   信号词：too good to be true / 好得不像真的、perfect backtest / 完美回测。

## E — 可执行步骤

1. 为每个数据字段建立时间戳文档：列出策略使用的所有数据字段，
   明确每个字段"在实盘中最早可在哪个时刻获得"（例如：财报数据、指标数据的发布延迟）。
   完成标准：时间戳文档完成，每个字段有"可用时刻"标注。

2. 检查信号生成时刻与数据可用时刻的一致性：对每个数据字段，验证：
   信号生成时刻 T ≥ 数据最早可用时刻 T_data。
   完成标准：所有字段的 T ≥ T_data，无例外。

3. 检查标准化处理是否引入未来信息：若使用z-score或百分位排名，
   验证计算均值和标准差的窗口是否仅使用当前时刻之前的历史数据（滚动窗口），
   而非全样本。完成标准：所有归一化操作使用滚动历史窗口，窗口终点不超过T。

4. 检查复权方式：若使用除权数据，选择后复权（以上市日为基准）而非前复权，
   或明确记录复权数据的历史改写风险。
   完成标准：复权方式有文字说明，前复权数据的风险已评估。

5. 执行"实盘模拟"验证：将回测框架切换至"逐日前进"（point-in-time）模式，
   在每个T时刻，只允许使用T之前已确认发布的数据，重新运行回测。
   若结果与原回测差异巨大，说明存在未来函数。
   完成标准：point-in-time回测完成，与原回测差异已量化分析。

6. 对异常优秀的回测结果进行未来函数审计：当回测年化收益>30%且最大回撤<10%时，
   强制执行上述1-5步的完整检查，不允许直接上线。
   完成标准：审计报告完成，有明确的"无未来函数"结论或已修复记录。

## B — 边界

**不适用场景：**
- 在使用明确标注了point-in-time数据的专业数据库（如Compustat PIT、Wind点时态数据）
  且数据提供商已处理时间戳问题的情况下，本反例的部分风险已被数据层缓解，
  但仍需验证下游处理步骤是否引入了新的未来函数。
- 纯理论研究或学术回测中，使用未来数据用于验证"如果信息完全已知，最大收益是多少"
  是合法的研究方法，但必须明确标注，不能直接应用于实盘策略。

**作者警告的失败模式：**
- 将回测框架中的"方便计算"（用全样本均值归一化）误认为"对历史真实的还原"。
- 以财报"报告期"而非"发布日"作为数据可用时间，系统性地提前了数据可用时刻。
- 在机器学习特征工程中，使用了包含未来标签信息的特征（数据泄露 / data leakage）。

**盲点：**
- 某些形式的未来函数极为隐蔽，例如：使用了已被上游数据提供商回溯修正的历史数据，
  而修正本身包含了事后才获得的信息（survivorship bias 的变体）。
- 即使完全消除了未来函数，回测过拟合（overfitting）仍然可能导致实盘失效；
  未来函数只是"回测好、实盘差"的原因之一，不是全部。
- 在高频策略中，微秒级的时间戳管理极为重要，粗粒度的日级时间戳检查不足以覆盖
  高频场景的未来函数风险，需要更精细的时序对齐。
