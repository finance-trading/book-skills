# 第2章：Hackers and Painters（黑客与画家）

## Core Idea
黑客不是科学家，也不只是工程师，而是 **maker（创作者）**——和画家、作家、建筑师、作曲家一样，目标是做出好东西。因此理解黑客最好的类比不是计算机科学，而是绘画：边画边改、以作品集学习、对美偏执、为人类观众设计。 empathy（共情）是区分好黑客与伟大黑客的单一最重要因素。

## Frameworks Introduced
- **Maker / scientist / engineer 三分**：科学家研究"是什么"，工程师解决"怎么做"，maker 决定"做什么"并把它做好。建筑与工程的分界在 what 与 how 之间；把三者塞进"计算机科学"系，会逼黑客假装做科学、写论文，从而从"做美的东西"漂移到"做适合写论文的丑东西"。
- **编程即素描（Programming as sketching）**：不应先在纸上完整设计再上机；应像画家一样先快速铺出破破烂烂的草稿，再逐渐修成形状。由此推出语言设计原则：语言首先是 **思考程序的工具**，不是表达已想好程序的工具——"它应该是一支铅笔，而不是钢笔"。
- **Day job（日间工作）**：几乎所有 maker 早期都有一份为钱的工作和一份为爱的工作；开源就是黑客的 day job 模式，且被其他创作者独立验证过。
- **绘画式协作**：画家合作时从不覆盖彼此的工作，而是分区域——大师画主体，助手画背景。软件协作也应划分为边界清晰的模块，每块有明确所有者，接口像编程语言一样精心设计。
- **"A great painting has to be better than it has to be"**：伦勃朗/达·芬奇在没人会细看的地方也全力以赴；未见的细节在总体上会变成可见的品质。伟大软件同样需要对美的狂热。
- **Empathy 框架**：软件是给人看的；要从用户视角看世界。测试方法：看一个人能否向非技术背景者解释技术概念。共情不等于自我牺牲——战争中理解敌人视角正是为了反制。

## Key Concepts
- **Computer science**：一个历史意外拼成的杂物袋，两端是数学家和黑客，中间是算法自然史；名字误导黑客去模仿科学。
- **Software engineering**：同样误导；优秀软件设计师更像建筑师而非工程师。
- **Premature design**：和过早优化一样危险——过早决定程序该做什么。好语言应像油画颜料，让人容易改主意。
- **Math envy**：科学家的通病，让工作看起来越数学越体面，于是去解可形式化的问题，而不是重要的问题。
- **Design by committee**：大公司用委员会设计来降低结果标准差，却也丢掉了高点；"大公司靠比别人少烂一点取胜"。
- **Day job / open source**：为钱做乏味问题，为爱做漂亮软件；招聘时应看候选人业余写什么。
- **Time as the only external test**：美的东西长期留存，丑的被丢弃，但时间尺度可能超过人的寿命。

## Mental Models
- 把编程语言想成**铅笔而不是钢笔**：允许涂改、涂抹、弄脏，才配得上探索性的工作。
- 把大公司想成**城堡**：正面进攻很难；设计战要打在新市场，那里还没有防御工事。
- 把代码想成**给人类读者的散文**："程序首先是写给人读的，只是顺便让机器执行。"
- 把职业想成**作品集**：画家按时间顺序留下作品，每幅都建立在前一幅学到的东西上；黑客也可以定期从零重画，而不是在一个项目上堆十年补丁。

## Anti-patterns
- **把黑客当科学家**：为了发表而选择"没人要的处女地"和"能写出臃肿论文的别扭系统"，会系统性地生产丑软件。
- **过早设计**：在需求会变时锁定规格；正确做法是保持语言抽象、程序短小、可随时改动。
- **委员会设计**：为了避险而抹平方差，结果失去伟大产品的可能。
- **数学嫉妒**：用希腊字母变量装点门面，回避真正重要但不易形式化的问题。
- **把共情误解为顺从**：共情是理解他人如何看世界，不是照单全收他人的要求。
- **在别人的画上作画**：多人无主地改同一段代码，会变成"公共休息室"——荒凉、失修、堆满垃圾。

## Worked Example
**从研究生院到艺术学校**：格雷厄姆在计算机系被教导"先在纸上把程序完全想清楚，再靠近电脑"，但他实际的工作方式是先吐出一堆 hopelessly broken 的代码，再逐步敲打成形。他一直为此感到羞愧，直到在画室看到画家和建筑师工作，才意识到这有名字：**sketching**。这个认识直接推出两个设计结论：(1) 语言必须可延展，允许你边写边想；(2) 静态类型只在"人真按学院教的方式写程序"时才合理，而优秀黑客并不那样写。

**Viaweb 被 Yahoo 收购后**：他以为"我只想 hack"，到 Yahoo 才发现那里的 hacking 意味着实现，而不是设计；程序员被当作把产品经理的"愿景"翻译成代码的技术员。这解释了为什么初创公司能在设计战中赢：新市场没有城堡，且同一个人同时设计与实现。

## Key Takeaways
1. 用 **maker** 而非 scientist 的身份定位自己，才能理直气壮地追求美，而不是追求论文。
2. 语言要像铅笔：**短、抽象、可改**；"最容易改的程序是短程序"。
3. 对未见之处也全力以赴——**总体品质由看不见的细节累积而成**。
4. 共情是可训练的成功技能；不能从用户视角看问题的人做不出伟大软件。
5. 若想靠软件赚钱又要做美的东西，接受 **day job** 结构，别指望市场为你的乐趣付高价。
6. 设计战要选**新市场**；在别人的操作系统垄断城堡里单挑，赢了也没人注意。
