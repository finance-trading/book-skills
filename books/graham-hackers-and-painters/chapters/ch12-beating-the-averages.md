# 第12章：Beating the Averages（击败平均水平）

## Core Idea
如果一家创业公司做所有创业公司都在做的事，它只能得到平均表现；而平均表现意味着倒闭（创业存活率远低于 50%）。所以创业公司**必须做点奇怪的事**。Viaweb 的"奇怪"是：在服务器软件中自由选择语言，并选了当时被视为怪异的 Lisp。Lisp 更强大、开发更快，而竞争对手的"Blub 悖论"使他们永远看不清这一点——这就是创业公司的"秘密武器"。

## Frameworks Introduced
- **平均表现 = 死亡（Average performance means you go out of business）**：大公司按行业平均做法能活（年增长约 10%）；创业公司照做则得到平均值，而创业公司的平均值是死亡。因此必须刻意偏离常规。
- **Blub Paradox（Blub 悖论）**：假设有一种中等能力的语言 Blub。Blub 程序员往下看，能看出更低级的语言缺什么；往上看，却看不出自己在往上看，只觉得更强大的语言"很奇怪、大概和 Blub 差不多，只是多了些毛茸茸的东西"。因此只有理解最强语言的人，才能看清整个能力谱系。
- **语言能力连续谱**：机器语言 → Cobol → Blub → …… → Lisp。高级语言并非等价；Perl 4 与 Perl 5 的差异（lexical closures）就证明一种高级语言可以比另一种更强。
- **Macros（Lisp 的杀手锏）**：Lisp 代码由 Lisp 数据对象构成；源码解析后就是可遍历的数据结构。Lisp 表面上有"奇怪语法"，实际上是**没有语法**——你直接写编译器内部会生成的 parse tree。因此可以写"写程序的程序"。
- **Aikido for startups（创业公司的合气道）**：编程语言不只是技术，还是程序员的**思维习惯**，所以"中位语言"像冰山一样移动缓慢。你无法对抗这股力量，但可以借力：当竞争者被粘在中位语言上时，你用更强语言获得的优势会被放大。
- **Job listings as intelligence（招聘广告即情报）**：评估竞争者最可靠的方式是看招聘要求。要求 Oracle 的最安全；要求 C++/Java 的也安全；要求 Perl/Python 的才开始像"技术由真正黑客掌舵"的公司。

## Key Concepts
- **Secret weapon**：Viaweb 用 Lisp 且不公开宣传；竞争对手以为他们破解了 Enigma，实际只是开发速度快到不可想象。
- **Power continuum**：语言按抽象能力排列；"能在更少元素里表达更多"就是更强。
- **Bottom-up / macros**：Viaweb 编辑器约 20–25% 是 macros；macros 难写，非必要不用，所以每一处都说明"这是别的语言难以轻易做到的"。
- **Median language**：中位程序员使用的语言；变化极慢——垃圾回收 1960 年由 Lisp 引入，动态类型正在普及，lexical closures 才刚上雷达，macros 仍是未知领域。
- **All-or-nothing startup**：押错技术，竞争者会碾碎你；因此技术选择不能按"别人都在用什么"。
- **Technology choice rule**：忽略别人在做什么，只考虑什么最有效；否则"你会去用 Windows"。

## Mental Models
- 把竞争者的语言选择想成**冰山**：它移动得极慢，你可以借它的惯性把对手困住。
- 把 Lisp 想成**没有语法**：你直接在编译器内部的数据结构里编程；macros 是"程序生成程序"。
- 把创业公司想成**必须偏离均值的学生**：做平均作业，只能得平均分；平均分在这门课里是不及格。
- 把语言能力想成**视力**：Blub 程序员不是不聪明，而是戴着一副只能看到某一层的眼镜；他无法评价更高层。
- 把招聘广告想成**X 光片**：营销话术可以伪装，技术要求必须具体，否则招错人。

## Anti-patterns
- **按"别人都在用"选技术**：这是大公司的策略；创业公司照做等于选择平均，也就是死亡。
- **相信"所有语言等价"**：这是 Blub 悖论的社会版本；说这话的人通常只在中位语言里写过 Pascal 式子集。
- **担心"找不到 Lisp 程序员"**：软件最好由少于十人的团队开发；任何听说过的语言都能找到十个人。找不到，可能是城市不对。
- **向 VC / 收购方设计产品**：应该向用户设计；赢了用户，其余自然跟随。
- **公开炫耀技术优势**：创业公司应给竞争者尽可能少的信息；"在商业中，竞争对手不理解的技术优势最有价值"。

## Worked Example
**Viaweb 的 Lisp 实验**：假设是——用 Lisp 能比竞争者更快做完功能，做到他们做不到的事；因为 Lisp 高层，不需要大团队，成本更低；于是能更便宜地提供更好产品，赢走用户，竞争者出局。结果：竞争者约二三十家，软件都停留在 CGI 脚本水平；Viaweb 有服务器端运行的 WYSIWYG 商店编辑器，感觉像桌面应用，功能始终领先。竞争者发布新功能后，Viaweb 有时一两天内就复制出来；记者打电话时，他们已经有了。最终以 1,070 个用户被 Yahoo 收购；后来作为 Yahoo Store 超过 20,000 用户。

**macros 的证据**：Viaweb 编辑器源码约 20–25% 是 macros。macros 比普通函数难写，风格上非必要不用，所以每一处都"必须存在"。这意味着至少五分之一的代码在做"其他语言里很难做的事"；而正是这些代码让软件做到了竞争者做不到的事。

**招聘广告情报**：Viaweb 每月冒出新竞争者。格雷厄姆先看是否有在线 demo，再看招聘广告：IT 味越重越不可怕；要 Oracle 的最安全；要 C++/Java 也安全；要 Perl/Python 才开始令人紧张——那说明技术侧至少由真正的黑客掌舵。

## Key Takeaways
1. 创业公司**必须偏离平均**；平均表现等于死亡。
2. 语言能力是真实的连续谱；**能用最强语言时，用较弱语言是一种错误**（程度不同，性质同手写机器码）。
3. Blub 悖论让你无法依赖中位程序员的判断；要自己爬到能力谱系上端去看。
4. Lisp 的优势来自**代码即数据 + macros**；这不是魔法，是可解释的机制。
5. 把竞争者的思维惯性当**杠杆**：他们越被中位语言粘住，你的优势越大。
6. 创业公司应**保密技术优势**，并把"用户"而非"VC/收购方"作为设计目标。
