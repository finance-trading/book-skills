# 第8章：A Plan for Spam（反垃圾邮件计划）

## Core Idea
垃圾邮件的**阿喀琉斯之踵**是它必须送达消息；其他屏障都能绕过，内容不能。因此内容过滤是根本解。最有效的方法不是手写特征规则，而是**贝叶斯统计过滤**：按每个词在垃圾/非垃圾语料中的出现概率组合判断。其最大优势是随着垃圾邮件演化而自动演化，并且只有把垃圾邮件逼到"无法再像正常邮件"时，才真正让它失去商业可行性。

## Frameworks Introduced
- **内容过滤是唯一不可绕过点**：发件人可以换服务器、伪造头、换地址；但为了有效，仍必须把销售信息送到收件人眼前。识别消息本身，是他们绕不过去的。
- **贝叶斯逐词概率**：分别统计 spam 与 non-spam 语料中每个 token 的出现次数，计算"包含该词的邮件是垃圾的概率" P(spam|w)，再取"最有信息量的 15 个 token"组合成整封邮件的概率。
  - 偏差修正：把 non-spam 计数加倍，保护"偶尔出现在正常邮件里的词"；只考虑总出现 >5 次的词；只在一侧出现的词给 .01/.99；未见过词给 .4；阈值 >.9 判为垃圾。
- **每用户语料（per-user corpus）**：每个用户有两个删除按钮——普通删除、删除为垃圾。各自积累自己的 spam/non-spam 语料，形成个性化概率。
  - 好处：更有效；用户自己定义什么算垃圾；使垃圾发送者难以针对"种子过滤器"调参。
- **White list 是计算优化，不是过滤核心**：保留你发过信的地址、普通删除的地址；但由于人有多个地址，不能对未知地址过度严格，否则制造 false positive。
- **让垃圾邮件不经济（make spam unprofitable）**：垃圾是生意；响应率极低（最好约 15/百万，目录直邮约 3000/百万）但发送成本几乎为零。过滤降低响应率，或迫使销售话术稀释到"Hey there. Check out the following: URL"，都会让更多商家觉得不划算。
- **对抗性检验（"if spammers knew exactly what you were doing"）**：任何方案都要回答：对手知道你的方法后，能怎么绕？贝叶斯过滤要求垃圾邮件在正文和头部都变得**与正常邮件不可区分**，这会严重限制其销售能力。

## Key Concepts
- **False positive**：正常邮件被误判为垃圾；对多数用户，漏掉一封正常邮件比收到垃圾坏一个数量级，因此过滤器必须偏保守。
- **Feature-recognition filter**：手写规则/打分（如 SpamAssassin）；问题是"分数"含义不明，且最后几个百分点极难，规则越严 false positive 越多。
- **P(spam|w)**：给定词 w 时邮件为垃圾的概率；`sex` 约 .97，`sexy` 约 .99，两者同时出现（在无其他证据时）约 99.97%。
- **Interesting tokens**：概率离 .5 最远的 15 个词，信息量最大。
- **Spam as business**：反垃圾不是道德战，而是降低对手的响应率与利润。
- **Pesticide analogy**：多数反垃圾技术像农药，只制造抗药新种；贝叶斯过滤器则随垃圾演化。

## Mental Models
- 把过滤器想成**每个用户自己的免疫系统**：种子过滤器只是出生时的抗体，真正的免疫力来自接触过的邮件。
- 把垃圾邮件想成**销售员**：它必须说服；一旦被迫只能发"看看这个链接"，说服力就消失了。
- 把 false positive 想成**化疗副作用**：疗效再好，如果会杀死病人（误删正常邮件），就不可接受。
- 把特征工程想成**和垃圾发送者下棋**：你越研究他的套路，越会被他下一步牵着走；统计方法则让数据自己找模式。

## Anti-patterns
- **手写特征直到最后几个百分点**：越严格，false positive 越多；且要不断进入垃圾发送者的心智，既低效又令人沮丧。
- **使用不可解释的"垃圾分数"**：用户和开发者都不知道分数意味着什么；概率至少含义明确，证据组合方式也明确。
- **对未知发件人过度严格**：老友可能换地址；这会制造最不可接受的 false positive。
- **只防当前垃圾**：垃圾会演化（viagra → v1agra）；静态规则会被抗药性击败。
- **以为更严的法律能直接减少垃圾量**：法律未必减少发送量，但能帮助过滤器减少收件人**看到**的量。

## Worked Example
**过滤器的工作流**（格雷厄姆亲自实现的版本）：
1. 准备两个语料，各约 4,000 封：spam 与 non-spam。
2. 扫描整封邮件（含头部、内嵌 HTML/JS）；把字母数字、连字符、撇号、美元符号视为 token 的一部分，其余为分隔符；忽略纯数字 token 和 HTML 注释。
3. 统计每个 token 在两个语料中的出现次数，得到两张哈希表。
4. 计算 `P(spam|w)`：`rg = min(1, 2*good(w)/G)`，`rb = min(1, bad(w)/B)`，`P = max(.01, min(.99, rb/(rg+rb)))`；把 good 计数加倍以偏向减少 false positive；只保留总出现 >5 次的词。
5. 新邮件到来，取概率离 .5 最远的 15 个 token，用贝叶斯组合计算整封概率；> .9 判为垃圾。
6. 结果：在作者自己的邮件上，**每 1,000 封垃圾漏检少于 5 封，0 个 false positive**。

**为什么过滤器能"学会"私人密码词**：作者常收到含 "Lisp" 的邮件而从未收到含该词的垃圾，于是 "Lisp" 实际上成了通行密码；他原先手工维护的"白名单词"（Lisp、邮编）被贝叶斯过滤器自动发现了，还发现了更多他没想到的词。

## Key Takeaways
1. 反垃圾要打**消息内容**这个不可绕过点，而不是不断封堵可绕过的通道。
2. 用**概率**而非魔法分数；概率可解释、可组合、可校准。
3. **每用户语料**既提高准确率，又让对手无法用一套调参通吃所有人。
4. 把 false positive 当作首要风险；宁可漏一点垃圾，不可误杀正常邮件。
5. 终极目标是让垃圾**不经济**：压缩其话术空间，降低响应率。
6. 任何过滤方案都要通过"对手知道你的方法"这一压力测试。
