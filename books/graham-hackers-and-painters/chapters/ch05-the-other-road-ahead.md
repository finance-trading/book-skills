# 第5章：The Other Road Ahead（前方另一条路）

## Core Idea
软件正在从桌面搬到服务器，用浏览器作界面。这条路会让用户更省事、更便宜、更可靠，也会让开发者以全新方式工作：没有"发布"，只有持续的小改动；没有大团队，只有少数全能黑客；没有平台守门人，直接通过浏览器把软件送到用户面前。对创业公司而言，这是一条**绕过 Windows 城堡**的解放之路。

## Frameworks Introduced
- **Web-based application / ASP 模型**：程序跑在服务器上，网页是 UI。用户只需浏览器；数据属于"你"，不再属于"你的电脑"。
  - 用户收益：随处可用、无需安装、自动升级、所有人同版本、bug 即刻修复、天然多人协作、数据备份更可靠、病毒暴露面更小。
  - 开发者收益：可任选语言、硬件可控、能观察真实用户、订阅收入、无盗版（但也失去"盗版作为最低价格歧视层"的好处）。
- **City of code（代码之城）**：web 应用不是单一二进制，而是多种程序组成的城市——建筑之外还要道路、路牌、水电、警察消防、增长与灾难预案。
- **Releases as increments（增量发布）**：桌面软件一年一两次"大爆炸"发布，导致批量 bug、QA 数 bug、修不完；服务器软件每天 3–5 次小改动，知道该重点测什么（最后改的东西），bug 少且"新鲜"，修复容易。
- **Brooks in reverse（布鲁克斯反演）**：人月神话说加人会让项目变慢；反过来，团队越小，开发效率指数级提高。Viaweb 只有三个程序员，几乎从不开会。
- **"You can, so you must"**：服务器软件让你能用任何语言、能持续发布、能 16 小时工作；因为竞争对手也能，你**必须**。
- **Just good enough（够用即可）**：网页不是为应用 UI 设计的，但"够用"；就像早期微处理器本是为红绿灯设计，却足够造出 Altair。够用 + 无处不在 > 精致 + 需安装。
- **Run upstairs（往楼上跑）**：被大块头追进楼梯间时往上跑——你的负担重，但他的块头更是劣势。初创公司应主动选择更难的技术问题，让大公司追不上。

## Key Concepts
- **Thin client**：客户端不存数据，像电话；"your computer" 变成 "your data"。
- **Application Service Provider (ASP)**：Viaweb 当年的名字；Hotmail 之后大众才理解。
- **版本号是 PR 发明**：trade press 按版本号思考；Viaweb 为曝光假装发布新版本，实际软件持续演化。
- **Compound bugs**：两个独立 bug 交互，最难找、后果最坏；增量发布让地板常扫，减少复合 bug。
- **Functional programming**：避免副作用，便于测试小改动；Viaweb 的 RTML 是纯函数式语言。
- **Support as QA/marketing**：支持人员离程序员 30 英尺，能复现 bug、判断功能困惑、充当焦点小组。
- **Price discrimination / piracy**：软件边际成本近零，盗版实际上是最低价格层；服务器软件取消盗版，也取消这一层。
- **Larval startup**：最早期的创业公司极其脆弱，任何显著障碍都会致命；桌面/大型机软件的前期承诺太重，所以当年创业公司少。

## Mental Models
- 把桌面软件时代想成**早期汽车**：要成为专家才能拥有；服务器软件是"把修车厂从你家搬走"。
- 把 web 应用想成**城市而非建筑**：只写"楼"（应用）而不修"路"（后台、备份、监控）会塌。
- 把发布想成**冲马桶 vs 修大坝**：小改动是持续冲走松动物体；大发布是拆掉半座坝再数漏洞。
- 把大公司想成**城堡**：它靠"比别人少烂一点"取胜；新市场没有城墙，才是设计战的地方。
- 把创业公司想成**幼虫**：任何 upfront commitment 都可能杀死它；低成本、可实验是生存条件。

## Anti-patterns
- **桌面式大发布**：一次换掉一半代码、批量 QA、修不完的 bug，最终对 bug 产生宿命论，甚至发布已知坏功能。
- **按版本号思考**：版本号是 PR 需求，不是产品现实；它会诱导你在某个日期前承诺"完整交付"。
- **通过 ISP 转售 web 软件**："像通过自动售货机卖寿司"——你放弃服务器控制，就放弃了这个模式的大部分优势。
- **为大客户做昂贵定制**：有钱客户倾向买贵方案，因为卖贵方案的人更能花钱推销；结果常常更差（圣诞流量一来就垮）。
- **把"web UI 不精致"当否决理由**：够用 + 随处可用 + 多人实时，常常压倒精致。
- **让不懂设计的 product manager 决定设计**：软件必须由懂设计的黑客设计。

## Worked Example
**Viaweb 的 test drive**：整个网站像一支指向试用的大箭头。试用约五分钟，结束时用户真的建好了一个能用的商店。格雷厄姆研究点击流，发现某一步用户会困惑并点浏览器的 Back 按钮；他在那里加了一句"你快完成了，别点 Back"。完成率立刻从 **60% 升到 90%**；由于新用户数正比于完成试用数，收入增长随之提高 **50%**。这是"观察真实用户 → 小改动 → 即时反馈"的完整闭环。

**launch 成本**：Viaweb 用不到 **$10,000** 上线（服务器 + SSL 是大头），三个家伙在公寓里、服务器托管在 ISP；今天同样的东西比一把 fancy office chair 还便宜。这解释了为什么服务器软件这一次会赢：**创业公司写得起**，而当年大型机软件要求昂贵的开发机和销售队伍，把幼虫阶段的创业公司直接挡死。

## Key Takeaways
1. 把软件搬到服务器，是把"系统管理员的负担"从用户转移给开发者；用户得到的核心价值是**省事**。
2. 发布节奏决定 bug 结构：**小步持续发布**比年度大爆炸更可靠，也更有士气。
3. 团队规模是架构决策：**小、全栈、有明确 owner** 的团队在服务器软件上指数级更高效。
4. 新市场里，**设计与实现同一批人**能打赢委员会设计的大公司。
5. 创业只需要懂两件 business：**做出用户爱的东西，并让收入大于支出**；其余边做边学。
6. 主动选**更难的技术地形**（run upstairs），那是大公司追不上的地方。
