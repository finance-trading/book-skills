# 第10章：Programming Languages Explained（编程语言解释）

## Core Idea
编程语言是**思考程序的工具**，而不只是把已想好的程序翻译给机器的格式。机器语言只提供最原始的动作；高级语言让你用更大的概念搭程序，因此程序更短、更易读、更可移植。语言之间的差异是真实的：抽象层次、静态/动态类型、面向对象的强制程度，都会改变你能想到什么、写出什么。开源则把"读源码、改源码"的控制权交还给使用者。

## Frameworks Introduced
- **机器语言 → 汇编 → 高级语言**：机器语言是计算机能执行的全部指令；汇编只是给这些指令起人类可读的名字。机器指令极其原始——让机器响十次都要手写循环和计数器，而且极易藏 bug。
- **编译器 vs 解释器**：编译器把高级语言整体翻译成机器语言；解释器逐段检查并执行对应机器指令。高级语言还带来可移植性：换机器只需重写编译器，不必重写所有程序。
- **Source code vs object code**：源码是你写的；目标码是翻译结果。商业软件通常只给目标码，目标码难读，实际上像加密，保护商业机密。
- **开源的控制权框架**：开源不仅让你能修 bug，更让**所有人**能修；像经过同行评审的论文，Linux/FreeBSD 的源码被许多聪明人看过，大部分 bug 已被发现。专有系统只能依赖大公司的 QA。
- **抽象度连续谱**：C 接近"可移植汇编"，Lisp 很高层；但"更抽象"不总是更好——Prolog 提供了强大的抽象，却只适用于约 2% 的问题，其余时间你在反向扭曲去误用它。
- **Seat belts or handcuffs?（安全带还是手铐？）**：语言设计的大辩论——语言应阻止程序员做蠢事（Java），还是允许程序员做任何事（Perl）。子辩论包括静态 vs 动态类型、面向对象的强制程度。
- **Top-heavy language**：内核设计一般，但有极其强大的库（"一辆在车顶焊了喷气引擎的 Yugo"）；对日常小问题，库可能比内核更重要。
- **Language renaissance**：硬件便宜后，高中生也能设计语言；开源社区能迅速提供大量代码；结果是语言多样性和"语言战争"——而文艺复兴本身也充满战争。

## Key Concepts
- **Machine language**：计算机能执行的全部指令集合。
- **Assembly language**：与机器指令一一对应，但用可读名称。
- **High-level language**：提供"做 n 次"这类强大命令，让程序更短、更易看出 bug。
- **Compiler / interpreter**：翻译器 vs 逐段执行器。
- **Static vs dynamic typing**：写程序时是否必须知道每个变量的类型；静态有助于防 bug 和生成快代码，动态给程序员自由。
- **Object-oriented programming**：把代码按"类"组织，每个类带自己的方法；优点是加新类型不必看旧代码，缺点是"不看旧代码就加东西"在软件里和在建筑里一样危险。
- **Open source**：拿到源码并能修改；可靠性来自更多人审查，而不仅是"免费"。
- **Language wars**：语言选择常被习惯与部落认同扭曲；"如果你只吃麦当劳，会觉得每个国家的食物都差不多"。

## Mental Models
- 把机器语言想成**只能开关电水壶**：能做的事极少；高级语言是给你一整套厨房设备。
- 把语言想成**积木**：高级语言给你更大的积木，所以同样的墙用更少块；但积木形状不对（Prolog）时，你会在错误的地方使劲。
- 把编译器想成**助手**：你写"做十次 beep"，它替你写无 bug 的汇编。
- 把开源想成**同行评审**：不是因为免费，而是因为可检查、可修改、可共同修复。
- 把语言战争想成**饮食偏好**：你长期吃一种，就觉得别的味道很怪；这不证明别的语言客观更差。

## Anti-patterns
- **"所有语言都差不多"**：Fortran I 与最新 Perl 之间、Perl 早期与后期之间，差异巨大；说这话的人通常只在用 Pascal 式原始子集。
- **只用自己习惯的语言评判所有语言**：长期使用一种语言会让你"用它思考"，别的语言显得笨拙，但这可能是习惯效应。
- **盲目追求最高抽象**：Prolog 式"强大但错误"的抽象会让你用 98% 的时间绕路。
- **强制面向对象**：允许你写 OO 的语言至少不差于强制你写的语言；强制只是限制自由。
- **把目标码当源码**：读不懂、改不了、只能等厂商修；在需要可靠性时这是真实风险。
- **把"库多"当语言好的全部理由**：库确实重要，但内核糟糕会让语言在复杂问题上崩溃。

## Worked Example
**让机器响十次**：机器语言需要"把 10 放进内存位置 0；如果位置 0 为负，跳到 b；beep；位置 0 减 1；跳到 a；b：……"。格雷厄姆故意把 10 写成 10，结果实际会响 **11** 次——"你为了让机器做一件事要说得越多，越难看出 bug"。高级语言只需 `dotimes 10 beep`，长度约为五分之一，错误一眼可见。

**圆和方的面积**：非 OO 写法是一个代码块里判断"问的是圆还是方"，再套对应公式；OO 写法是建 `circle` 和 `square` 两个类，各带一个求面积的 method。运行时做的事几乎相同，但代码组织不同：OO 版本把圆的代码和方的代码分到不同文件，增加三角形时只需加一块，不必看其余部分——代价是"不看旧代码就加东西"可能让系统像乱加盖的建筑。

**Viaweb 的 RTML**：把脚本语言设计成纯函数式，避免副作用，便于测试小改动；这与"服务器软件持续小步发布"的工作方式直接契合。

## Key Takeaways
1. 语言是**思维工具**：它决定你能用多大的概念搭程序，以及程序有多短、多可读。
2. 高级语言的三个直接收益：**更短、更少 bug、更可移植**。
3. 抽象不是越高越好；要问"这些抽象是否匹配问题"。
4. 静态/动态类型、OO 强制程度，本质是**自由 vs 保护**的权衡，没有无脑答案。
5. 开源的核心价值是**控制权与可审查性**，不只是价格。
6. 语言多样性是健康的：如果所有人用同一种语言，那很可能是错的那种。
