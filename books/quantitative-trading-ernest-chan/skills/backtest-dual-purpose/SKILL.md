# Backtest Dual Purpose — 回测目的双重性

## R — 原文 (Reading)

> "回测不仅仅是要做到应有的谨慎，更重要的是在回测中可以尝试修改原始策略，从而优化并改进策略...真正的窍门是：对基础策略进行变形，并用于赚钱...一项策略真正的独有价值和值得保密的地方是你自己的窍门和所进行的变形，而绝不是基础版本。"
>
> — Ernest P. Chan, 第2章 / 第3章

## I — 方法论骨架 (Interpretation)

回测不是"通过/不通过"的考试，而是 **发现和创新** 的工具。作者强调两重目的：

1. **复制验证（Replication）**：复现论文/论坛策略的回测，确认原作者没犯常见错误（前视偏差、存活偏差、忽略成本）。这是最低限度的严谨性要求，类比医学/自然科学的"复制研究"传统。
2. **变形优化（Variation）**：更重要！在已复制的基础上，尝试修改：
   - 持有期（缩短 / 延长）
   - 建仓 / 清仓时点（收盘 → 开盘）
   - 股票池（S&P 500 → 特定行业 ETF）
   - 参数微调（阈值、回溯期）

核心洞察：**基础策略几乎总是不赚钱**（竞争把利润套干了）；真正有价值的是你自己的变形窍门——这才是值得保密的部分，基础版本反而是可以公开的。

## A1 — 书中的应用 (Past Application)

### 案例 1: 财富实验室论坛策略变形（ca006）
- **问题**: 读者推荐了一个据称高夏普的策略，Chan 拿到后初步回测"完全没有声称的那样出色"。
- **方法论的使用**: 没有放弃，而是尝试变形——缩短持有期、改变建仓 / 清仓时点。
- **结论**: 变形后的策略成为作者"主要的盈利来源"。
- **结果**: 验证了"基础策略不行，但变形后可能成为金矿"的核心洞察。

### 案例 2: 清仓时点从收盘改为开盘（ca014）
- **问题**: Khandani-Lo 均值回归策略在考虑 5bp 成本后 S 从 +4.47 跌至 -3.19，几乎被判死刑。
- **方法论的使用**: 仅把"收盘更新头寸"改为"开盘更新头寸"——一个时点变化。
- **结论**: S 从 -3.19 升至 +0.78，重新变得有利可图。
- **结果**: 证明微小变形可以挽救被判死刑的策略，是"回测第二目的"的最生动演示。

## A2 — 触发场景 (Future Trigger)

### 用户会在什么情境下需要这个 skill?

1. 完美复现了论文的回测结果，问"接下来呢？直接实盘？"
2. 初步回测不合格，考虑放弃——需要先想是否已经尝试变形。
3. 已经有一个在用策略，想系统化地探索变形空间。

### 语言信号

- "复制了论文 / replicated the paper"
- "回测完成接下来呢 / what's next after backtest"
- "怎么改进策略 / how to improve the strategy"
- "要不要调参数 / should I tweak parameters"
- "基础策略不赚钱 / base strategy doesn't work"

### 与相邻 skill 的区分

- 与 `strategy-screening-six-questions` 的区别：六问在回测**前**做初筛；本 skill 在回测**后**做深度开发。
- 与 `parameter-complexity-overfitting` 的区别：变形时**必须**遵守参数上限，否则会陷入过拟合——本 skill 与后者配合使用。
- 与 `sharpe-ratio-supremacy` 的区别：本 skill 管"怎么改"，后者管"改完之后怎么比"。

## E — 可执行步骤 (Execution)

1. **复制验证**：完全按原始论文/论坛描述复现回测，不加任何修改。
   - 完成标准：复现结果与原作者报告数字误差 < 10%。
   - 判停条件：若误差 > 10%，先排查前视偏差、存活偏差、成本遗漏（转 `data-quality-traps`）。

2. **列出变形维度**：至少 4 个方向——持有期、建仓/清仓时点、股票池、参数。
   - 完成标准：每个维度列出 2-3 个候选值。

3. **系统性变形**：每次只改一个维度（单变量实验），在**样本外数据**上评估 S。
   - 完成标准：每个变形输出"训练集 S / 测试集 S"对。
   - 判停条件：若测试集 S 比原版更低，回退该变形；若更高，保留作为新基线。

4. **选择最终版本**：在所有通过样本外验证的变形中，选"测试集 S 最高且参数最少"的版本。
   - 完成标准：输出最终策略规格 + 与原始版本的对比表。

## B — 边界 (Boundary)

### 不要在以下情况使用此 skill

- 还没做复制验证就想变形——先确认基础版本没犯常见错误。
- 一次改多个维度——无法归因，会陷入过拟合。
- 没有样本外数据——变形会立即退化成数据迁就偏差（转 `parameter-complexity-overfitting`）。

### 作者在书中警告的失败模式

- **ce06**: 数据窥探偏差——变形同样要遵守参数上限，否则"优化"即"过拟合"。
- **ce13**: 人为干预——变形必须基于系统化实验，不能凭直觉拍脑袋。

### 作者的盲点 / 时代局限

- 书中案例多为日线级别策略；高频/分钟级策略的变形空间（如订单类型、执行路径）更丰富，书中未涉及。
- "变形是保密的"——在 2026 年开源文化和 alpha 共享平台（如 QuantConnect）时代，部分变形思路已可公开讨论而不失优势。
- 作者未讨论变形的"系统性穷举"方法（如网格搜索、贝叶斯优化），仅凭经验列举。

### 容易混淆的邻近方法论

- "变形" ≠ "参数微调" —— 变形包括结构性变化（时点、股票池、持仓期），参数微调只是变形的一种。
- "基础版本无效" ≠ "策略无价值" —— 往往是变形的起点，不是终点。
