# Simple First Principle — 简单至上原则

## R — 原文 (Reading)

> "我灰头土脸地离开了金融行业，在家中搭建了一个简易卧室作为我的交易办公室，开始进行一些最简单的量化策略交易。这些策略是任何一个头脑聪明的高中生都能轻而易举搞定的。那是我人生中，第一次建立起能获利的策略……正如爱因斯坦所说的：'任何事情都应该尽可能地简单，直到无法再简单为止'。"
>
> — Ernest Chan, 第1章 line 431-435

---

## I — 方法论骨架 (Interpretation)

这个原则的核心是：**策略的简单性与盈利能力成正比，而非反比**。

方法论骨架：
1. **反直觉观察**：机构追求复杂性（高深数学、复杂模型），结果是亏损；独立后使用简单策略（高中生都能理解），结果是盈利。
2. **结构性解释**：
   - 复杂模型更容易过拟合历史数据（参数多→数据窥探偏差）
   - 复杂模型对市场变化更敏感、更脆弱（状态转换时崩溃）
   - 简单模型更容易验证、调试、理解（避免软件风险）
3. **实操标准**：
   - 参数不超过5个（经验法则）
   - 模型应该能被"头脑聪明的高中生"理解
   - 如果需要高等数学才能理解，就过于复杂了
4. **哲学基础**：爱因斯坦——"任何事情都应该尽可能简单地简单，直到无法再简单为止"。奥卡姆剃刀——"能经得起时间考验的往往是简单的模型"。

关键洞察：**简单不是妥协，而是结构优势**。在小容量策略领域，简单性让你能快速迭代、避免过拟合、保持稳健。

## A1 — 书中的应用 (Past Application)

### 案例 1: 从机构亏损到独立盈利的亲身经历 (ca001)
- **问题**: Ernest Chan在康奈尔大学获得物理学博士后，在IBM沃森研究中心、摩根士丹利、瑞信等顶级机构工作，使用高等数学于统计套利交易，造成上亿美元亏损。
- **方法论的使用**: 离开机构后，在家搭建简易办公室，放弃复杂数学模型，转向"任何一个头脑聪明的高中生都能轻而易举搞定的"简单策略。
- **结论**: 简单策略优于复杂策略。独立交易者在小容量策略上的优势是简单性，而非复杂性。
- **结果**: 三个月内找到第一个策略并回测，开立10万美元经纪账户，第一个月即盈利。验证了"简单策略+独立交易"的可行性。

### 案例 2: 财富实验室论坛策略的变形 (ca006)
- **问题**: 作者从博客读者处获得财富实验室论坛上的策略推荐，初步回测效果远不如声称。
- **方法论的使用**: 没有追求更复杂的模型，而是对基础策略进行**简单调整**：缩短持有期、改变建仓/清仓时点。
- **结论**: 现成策略经不起严格回测，真正有价值的是你自己的变形和窍门——而这些变形往往是简单的。
- **结果**: 变形后的策略成为作者主要的盈利来源。

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个 skill?

1. **纠结策略复杂度**：用户在学术策略和简单策略之间犹豫，认为"复杂=专业=有效"。
2. **机构环境压力**：用户在机构工作，被鼓励或要求使用复杂数学模型，但业绩不佳。
3. **回测过拟合**：用户的策略参数超过5个，回测业绩优秀但实盘表现差。
4. **追求"完美策略"**：用户花费大量时间优化复杂模型，而不是测试简单变形。

### 语言信号 (用户的话里出现这些就应激活)

- "这个策略太简单了，能赚钱吗？"
- "我需要一个更复杂的模型"
- "简单策略会不会太naive？"
- "这个策略有10个参数，是不是太少了？"
- "This strategy is too simple" / "I need a sophisticated model"
- "Can simple strategies really work?"

### 与相邻 skill 的区分

- **与 `strategy-modification-methodology` 的区别**: 本skill强调"为什么简单更好"（原则层面），strategy-modification强调"如何变形策略"（方法层面）。本skill回答"选什么样的策略"，strategy-modification回答"如何改进策略"。
- **与 `strategy-selection-four-constraints` 的区别**: 本skill是策略选择的**质量标准**（简单性），strategy-selection是**约束条件**（时间、资本、编程水平、目标）。本skill回答"好策略长什么样"，strategy-selection回答"我能用什么策略"。

## E — 可执行步骤 (Execution)

当 skill 被激活后, agent 应按以下步骤执行:

1. **评估策略复杂度**
   - 完成标准: 用户能列出策略的参数数量、所需数学知识水平、是否高中生能理解。
   - 判停条件: 若参数>5个或需要高等数学，进入步骤2；否则跳到步骤3。

2. **简化策略**
   - 完成标准: 用户能将参数减少到5个以内，用初等数学重新表述策略逻辑。
   - 判停条件: 若简化后回测业绩仍然可接受（夏普比率>1），进入步骤3；否则考虑strategy-modification-methodology。

3. **验证简单性优势**
   - 完成标准: 用户能用一句话向非专业人士解释策略逻辑。
   - 判停条件: 若无法一句话解释，返回步骤2继续简化。

4. **记录简单性检查清单**
   - 完成标准: 用户建立检查清单：参数数量≤5？高中生能理解？一句话能解释？
   - 判停条件: 清单全部通过，完成。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此 skill

- **学术研究场景**：如果用户在做学术论文，需要展示复杂数学推导能力，简单性不是优先目标。
- **高频交易核心算法**：某些高频策略确实需要复杂数学（如随机微积分），此时简单性不是主要考量。
- **策略已经很简单但失效**：如果策略已经很简单但仍然亏损，问题可能不是复杂度，而是市场状态转换或竞争加剧。

### 作者在书中警告的失败模式

- **ce01 - 在机构使用高深数学反而亏损**: 作者在顶级机构使用高等数学于统计套利，造成上亿美元亏损。失败模式：追求复杂性而非实用性，过度自信导致过度复杂化。
- **ce06 - 数据窥探偏差（过拟合）**: 参数越多（超过5个），越容易拟合噪声而非信号。回测业绩好但未来业绩差。
- **ce24 - 学术策略的局限性**: 学术策略往往过于复杂、已经过时、所需数据昂贵。简单策略在交易员论坛更容易找到和实施。

### 作者的盲点 / 时代局限

来自 BOOK_OVERVIEW.md 的批判：

1. **过度简化了机构交易的经验**: 作者将机构的复杂性等同于"错误"，但现实中机构的复杂模型可能服务于其他目标（风险控制、合规要求、多策略组合）。并非所有复杂性都是"不必要的"。
2. **2009年的工具建议已过时**: 书中推荐Excel/MATLAB/TradeStation，但2025年Python生态（pandas、backtrader、zipline）已成为主流。简单性的定义随工具演进而变化。
3. **忽视了简单策略的竞争劣势**: 简单策略容易被复制，一旦公开就迅速被竞争消灭。作者强调分享策略，但也承认"随着越来越多的交易员发现这些策略并且加入竞争，这些策略就会失去盈利潜力"。

### 容易混淆的邻近方法论

- **简单 ≠ 容易**: 简单策略的逻辑简单，但发现、验证、执行并不容易。需要大量回测、仿真、心理准备。
- **简单 ≠ 原始**: 简单策略可以是经过复杂分析后的提炼，而非未经思考的粗糙想法。
- **简单 ≠ 万能**: 简单性是小容量策略的优势，但大容量策略可能需要复杂性来处理多维度风险。
